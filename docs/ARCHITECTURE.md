# Breezy implementation contracts

## Product and identity

Breezy is a native iPhone and iPad streaming player for iOS 18+, with listening-led discovery, unrestricted Search, radio, lyrics and a local library. It runs on Apple silicon Macs as an iPad app (Designed for iPad); Mac Catalyst is not available because FFmpegBridge ships iOS slices only. Native watchOS 11+ and CarPlay interfaces control the same player. The selected name is `Breezy - Stream Music & Chill`; the Home Screen displays `Breezy`. Project/module/scheme `GanaBajana`, bundle ID `com.agraabhi.ganabajana`, URL scheme `ganabajana`, and `Application Support/GanaBajana` are stable identities.

**R9 source, 24 September 2026 UTC: uncommitted after `ebb5d5c`.** Uploaded build **1.0.0 (5)** includes R6/R7/R8/R9 and is `VALID`, App Store eligible and attached to the iOS draft. Required declarations block App Review; the app is not publicly released. [VERIFICATION.md](VERIFICATION.md) records current execution and completed rounds; [release status](app-store/RELEASE_STATUS.md) owns exact remote state and historical artifact provenance.

Recording-language/duration metadata uses the official YouTube Data API; the music catalog and extraction/caching integration remain unofficial, with the content-rights hold recorded in release status. These contracts describe source behavior. Native two-device iCloud, physical paired-Watch/CarPlay behavior, actual AirPlay receivers and hardware acceptance remain separate from fixture checks.

## Shared models

- `Track.credits: [ArtistCredit]` holds provider-order artist names and optional IDs. `artists`/`artistID` are derived; legacy stored tracks decode into credits. `Track.allCredits` adds artists named in title feature clauses. `CatalogPage.credits` carries album-header credits.
- `ArtistPage.monthlyAudience` retains the provider metric, numeric value, and raw display text. A listener count is not a monthly play count. Recording counts stay attached to recording IDs.
- `HomeLayoutPreferences` stores section order and hidden identifiers, preserving unknown identifiers across decoding. `UserPreferences` includes `homeLayout`, `accent`, `audioCacheLimit` and five independent `languageNudges` fields alongside playback, legacy discovery, DNS and history choices. `LanguageRecommendationNudge` has `automatic`, `more` and `less`; missing fields decode as Automatic.
- `ShuffleStyle.random/fewerRepeats` and `DiscoveryFamiliarity.familiar/balanced/newMusic` are independent scalar preferences. Missing values default to Random/Balanced; present invalid values fail decoding. Existing sparse journals require no synthetic revisions for these defaults. [Listening controls](LISTENING_DISCOVERY.md) owns weighting, actual familiar/new classification and metrics.
- `RadioConfiguration` retains an explicit Hindi/English language draft for legacy callers. Current `RadioSetupView` collects era and zero to four optional `ArtistCredit` hints, initially empty, then calls `startRadio(_:)` without an explicit language set. Automatic sessions capture `ListeningLanguageProfile`, which can target all five recording languages. `RadioExperience` retains Moods/Genres grouping, style templates and optional cue variants. Persisted queue state does not preserve a complete active radio session.
- `ArtistSongLanguageResult` distinguishes identified, likely, and unclassified results with provenance. Only identified results participate in language-specific filters; weak suggestions remain unclassified for filtering. Library overrides take priority over automatic evidence.
- `LyricsDocument` distinguishes synced, plain, instrumental, and unavailable content. A thrown lookup error is not an unavailable document. `LyricsRequestKey` includes recording ID and metadata so dubbed recordings cannot share a lyrics result accidentally.
- `AlbumDescription` retains the album ID/title/credits, supplied prose, Wikipedia article URL, supplied license and its URL, and excerpt status. `CatalogPage.albumDescription` is optional and defaulted; existing catalog implementations need not supply it.
- `SearchSelection` is `.track(Track)` or `.collection(MusicCollection)`. Identity includes the case-sensitive provider ID and collection kind, not title. A persisted collection selection has no track payload. `CachedSong`, `AudioCacheSnapshot` and `AudioCacheRemoval` project existing cache files rather than create a second library or downloader.
- `SourceAudioQuality: Codable, Equatable, Sendable` holds AAC-family or Opus codec metadata with optional bitrate, sample rate, and channels. `preferredBitRate(average:advertised:)` uses valid average bitrate first; `prefers(_:over:)` orders encodings by that value and prefers AAC on ties. This is a selection rule, not perceptual equivalence between codecs. `ResolvedStream.quality` and cache sidecars carry metadata without signed URLs; missing optional quality leaves legacy AAC entries usable.

## Provider APIs

The provider integration boundary uses [`ProviderProtocols.swift`](../Sources/Core/ProviderProtocols.swift), with the optional description capability declared in [`AlbumDescription.swift`](../Sources/Core/AlbumDescription.swift):

| Protocol | Contract |
| --- | --- |
| `MusicCatalogProviding` | `search(query:filter:continuation:)`, `browse(id:)`, `artist(id:)`, `recommendations(seed:language:)`, `radio(seed:)`, `radio(seed:forceRefresh:)`, and `discovery(languages:)`, all async/throwing |
| `MusicChartsProviding` | `weeklyChart(language:) async throws -> ChartSnapshot` |
| `LyricsProviding` | `lyrics(for:) async throws -> LyricsDocument` |
| `AlbumDescriptionProviding` | Optional capability: `albumDescription(id:) async throws -> AlbumDescription?`; nil is successful absence, while a thrown error remains retryable |
| `StreamResolving` | `resolve(track:forceRefresh:) async throws -> ResolvedStream`; `prefetch(_:) async` defaults to a no-op |

Concrete providers:

- `YouTubeMusicService: MusicCatalogProviding, LyricsProviding, AlbumDescriptionProviding` has defaulted `session` and `now` injection. Its lyrics method follows the selected recording's Lyrics-tab browse ID and returns plain text. `audioMetadata(for:)` batch-validates album-audio metadata. Ordinary album browsing carries a parsed description; `albumDescription(id:)` optionally reads only the first browse header through the same transport/cache.
- `YouTubeChartsService: MusicChartsProviding` selects weekly `TRACKS` entries with album-audio counterparts. Original ranks, dates, and region remain in the result.
- `YouTubeDataAPI.recordingLanguage(for:)` reads only exact-recording `snippet.defaultAudioLanguage`; `prepareForLookup(_:)` fills a missing duration in a temporary track copy. Known valid durations and saved metadata are preserved. [YOUTUBE_DATA_API.md](YOUTUBE_DATA_API.md) owns request fields, credential restrictions, cache/deadline/backoff limits, metrics and verification.
- `LRCLyricsService: LyricsProviding` performs recording matching. `CompositeLyricsProvider(primary:fallback:prepareTrack:configuration:now:)` optionally prepares a missing duration within its total deadline, then tries LRCLIB before the catalog's `LyricsProviding` fallback for missing/error results. Instrumental and usable primary lyrics stop the fallback. Its cache and concurrent requests are bounded.
- `ArtistSpotlightLanguageService.classification(for:)` reuses verified recording metadata and cached evidence, then checks `recordingMetadataLookup` before lyrics or recognition. Explicit audio-language results skip classification; absent/failed metadata keeps the concurrent lyrics and optional MusicBrainz path inside the original overall deadline. `Configuration.sourceTimeout` bounds each fallback source; `recordingMetadataTimeout` bounds the initial lookup. `ArtistSpotlightMusicBrainz.shared` requires the HTTPS `MusicBrainzContactURL` configured in `project.yml`. Its recording and conditional exact-work lookups share one rate limiter and provider deadline. [PROVIDERS.md](PROVIDERS.md#radio-and-language-evidence) owns those bounds.
- `YouTubeStreamResolver: StreamCacheManaging` has `init(allowRemoteFallback: Bool = false, isOffline: @escaping @Sendable () -> Bool = { false })` and an injected initializer with `qualityExtract`, `opusEnabled` and `opusTimeout`. Normal and forced resolution try compatible complete cached audio before requiring a network path. `refreshQuality(track:) async throws -> ResolvedStream` bypasses audio-cache selection only while not known offline, retaining a cached fallback after failure.

`StreamCaching` extends resolution with `download(_:)`, `discardCached(_:)`, variant-specific `discardCached(_:url:)`, `retainCached(_:)`, and `isCachedStream(_:)`. `StreamCacheManaging` adds `audioCacheUsage()`, `audioCacheSnapshot()`, `removeCachedSong(id:retaining:)`, `updateCacheListeningHistory(_:now:)`, clearing and cache-limit APIs. Optional inventory/removal defaults return nil, not a verified empty cache or successful deletion. Other resolvers need not own a production cache.

`URLSession.boundedData(for:maximumBytes:delegate:)` checks declared and incrementally received body size before returning data. Its optional task delegate lets the Data API refuse redirects before forwarding the credential. Early exit and caller cancellation cancel that request's task; HTTP status and payload validation remain caller-owned. The vendored extraction transport applies its own request budgets and cancellation, and concurrent player lookups use structured task groups. [PROVIDERS.md](PROVIDERS.md#response-limits-and-cancellation) owns the exact limits.

## LibraryStore API and durability

`LibraryStore.init(directory:now:)` uses `Application Support/GanaBajana/library.json` by default and permits an isolated directory/clock. Readable state includes library collections/history/preferences, `playback`, `pendingReleaseNotifications`, `tipCount`, `storageBytes`, `errorMessage`, `requiresReload`, and `hasLoadedDocument`. A genuine new empty library is loaded state; an unreadable startup placeholder is not.

| Operation | API |
| --- | --- |
| Likes/dislikes | `isFavorite(_:)`, `toggleFavorite(_:)`, `isDisliked(_:)`, `toggleDislike(_:)` |
| Playlists | `createPlaylist(name: String, tracks: [Track] = []) -> UUID`, `renamePlaylist(id:name:)`, `deletePlaylist(id:)`, `add(_:to:)`, `remove(trackID:from:)`, `moveTracks(in:from:to:)` |
| History/resume | `recordListening(track:sessionID:startedAt:seconds:) -> Bool`, `recordRecent(track:position:)`, `updatePlayback(_:)`, `clearHistory()`, `summary(for:now:)` |
| Search history | `recordSearchSelection(_:) -> Bool`, `removeRecentSearchSelection(id:) -> Bool`, `clearRecentSearches() -> Bool`; legacy `recordSearch(_:)` and `removeRecentSearch(_:)` remain for compatibility |
| Follows/mixes | `isFollowing(artistID:)`, `follow(_:)`, `unfollow(artistID:)`, `recordReleaseCheck(artistID:knownReleaseIDs:newReleases:checkedAt:catalogReadSucceeded:) -> Bool`, `markReleasesSeen()`, `mix(_:)`, `saveMix(_:)` |
| Release delivery | `canDeliverReleaseNotification(_:) -> Bool`, `acknowledgeReleaseNotification(id:) -> Bool` |
| Disk recovery | `reloadFromDisk() -> LibraryReloadResult`; app-facing `MusicAppModel.reloadSavedLibrary()` |
| Recording corrections | `lyricsOffset(for:)`, `setLyricsOffset(_:for:)`, `setRecordingLanguageOverride(_:for:) -> Bool` |
| Tip ledger | `tipCredit(for: UInt64) -> Bool?`, `recordTip(transactionID:credited:) -> Bool` |

The writable `preferences` property commits mutations. Views use `MusicAppModel.updatePreferences(_:)` so dependent services receive only the preferences actually saved. Each commit validates a candidate document, checks the prior bytes on disk, writes atomically, and publishes state only after success. Unreadable/future stores block writes. A stale writer cannot replace an externally changed library.

Playlist creation saves the trimmed name and recording-ID-deduplicated tracks in one commit, including the sync journal. The returned UUID alone is not a success acknowledgement: Queue Save checks that it exists in `playlists` and `errorMessage == nil`. Invalid metadata or a failed write publishes neither an empty placeholder nor a partial playlist.

`recentSearchSelections` holds at most 20 explicit destination selections, newest first. Reopening an item advances its revision even if it was already first locally. Collection tracks are stripped before validation/persistence. Legacy query strings remain in `recentSearches`, with no guessed conversion to entities. `clearRecentSearches()` atomically clears both fields and advances `searchReset`, including when already empty. Listening-history disable/clear is an independent boundary. [ICLOUD_SYNC.md](ICLOUD_SYNC.md) owns typed floors, revisions and schema compatibility.

Listening updates are delta seconds. A true acknowledgement means the delta was durably saved, or was a no-op for disabled history/zero time. `PlaybackListeningBuffer` retains unacknowledged deltas for up to 128 original session identities; delivery removes only acknowledged time. Capacity exhaustion pauses playback instead of dropping pending time. The buffer is memory-only and does not survive termination.

Clearing history or successfully disabling history changes the persisted privacy epoch and discards pending listening. Clearing also removes events, recents, and generated mixes, while preserving explicit library choices, queue, searches, and tips. `LibraryRecovery.crossesHistoryBoundary` also recognizes conservative legacy signals such as removed/reduced retained history, preventing an ordinary reload from resurrecting erased listening.

`reloadFromDisk()` validates and rechecks the bytes before adopting them, without itself writing a replacement. It returns `.reloaded`, `.historyBoundary`, or `.failed`; failure preserves the established document and blocks writes. `reloadSavedLibrary()` runs outside listening callbacks, retires stale personalization/radio work, reconciles playback/cache/DNS preferences, and then retries eligible buffered listening. A live queue takes precedence over a saved snapshot. Only an untouched failed-startup placeholder receives the recovered queue, restored paused. Lifecycle and restore-retirement callbacks cannot write that placeholder over repaired disk state. [PROVIDERS.md](PROVIDERS.md#local-data-and-backups) owns retention and backups.

## PlayerController API and lifecycle

`PlayerController.init(resolver: any StreamResolving = YouTubeStreamResolver())` is the single playback-state owner. Readable state includes current track/queue/index, position/duration, play/loading/error state, shuffle/repeat, sleep deadline, transition settings, normalization gain, resolved view count, `sourceAudioQuality`, `canReloadAudioQuality`, radio identity, `isNetworkOffline`, `isCurrentTrackCached`, `isNextTrackCached` and cache-management status.

- Selection and transport: `play(_:startingAt:isRadio:)`, `togglePlayback()`, `pause()`, `next()`, `previous()`, `seek(to:)`, `retry(preferBestAudio: Bool = false)`, `restore(_:)`.
- Queue: `toggleShuffle()`, `cycleRepeatMode()`, `enqueue(_:next:)`, `appendAutoplay(_:)`, `removeFromQueue(at:)`, `moveQueue(from:to:)`. Shuffle and repeat are surfaced in the Queue sheet's controls row, not the transport row.
- Settings and maintenance: `apply(_:)`, `setSleepTimer(minutes:)`, `setRemoteFallbackEnabled(_:)`, `setNetworkOffline(_:)`, `prefetch(_:)`, `flushListeningProgress()`.
- Storage: `audioCacheUsage() async throws -> AudioCache.Usage?`, `cachedSongsSnapshot() async throws -> AudioCacheSnapshot?`, `removeCachedSong(id:) async throws -> AudioCacheRemoval?`, `updateCacheListeningHistory(_:now:) -> Task<Void, Never>?`, `clearTemporaryAudioCache() async throws -> AudioCache.Usage?`, and `setAudioCacheLimit(_:) -> Task<AudioCache.Usage?, Error>`. The UI observes `isUpdatingAudioCacheLimit`, `audioCacheLimitError`, and `audioCacheLimitUsage`.
- Callbacks: `onListeningProgress(Track, UUID, Date, TimeInterval) -> Bool`, `onSnapshotChanged(PlaybackSnapshot)`, `onTrackStarted(Track)`, and async `onQueueExhausted(Track) -> [Track]`, asked when the last entry in play order starts and once more at the end of the queue when that early answer added nothing. `discardPendingListening()` retires buffered deltas at privacy boundaries.

Selection updates synchronously before cancellable resolution. Restore remains paused. Generation checks protect newer selections from late resolver, seek, radio, and transition callbacks. `PlaybackListeningClock` measures actual listening rather than seek distance. `PlaybackQueue` preserves the original queue through shuffle.

`setShuffleStyle(_:)` changes configuration only. The model installs `shuffleHistoryProvider`, returning current durable events only for a loaded, non-recovery, history-enabled library. `playShuffled(_:)` samples the first occurrence and remainder together; `play(..., shuffle: false)` selects an ordinary list without first changing the old queue. The optional override's nil default retains existing shuffle state for explicit selections. Queue, Watch and CarPlay toggles use the same policy.

`PlaybackSnapshot.originalQueueIndices` maps each playback occurrence to its position in `originalQueue`. New mappings are validated permutations with matching recording IDs, and unshuffled snapshots require identity order. Restore reuses live entries/metadata, so identical duplicates retain their selected occurrence. Legacy nil mappings keep best-effort track matching and remain absent through passive restore/checkpoints until an actual ordering/selection mutation. `updatePlayback` persists mapping-only edits without creating shared mutations.

`PlaybackCachePipeline` coordinates full-song downloads and pins. `StandbyDeck` and `PlaybackCrossfade` in `PlaybackTransition.swift` prepare and blend adjacent playback. Cache clearing or limit changes stop old writers and re-read the live retained set before removing unused files. In-use files can temporarily exceed the policy; storage UI reports them rather than claiming a zero-byte clear.

### Cached inventory and offline playback

`AudioCache.snapshot(allowOpus:)` groups complete sidecar/media pairs by recording ID, checks file size/type and selects an eligible encoding. `CachedSong.isPlayable` requires a provider recording ID and a compatible preferred local file. Unsupported encodings can remain visible as nonplayable storage; partial files never become song entries. This inventory does not fully decode AAC or establish that every byte will play. `preparedEntry(for:allowOpus:)` uses a native duration read when sidecar duration is missing, with a reader lease retained until native work unwinds. Playback can reject a damaged variant and try another local copy.

New audio sidecars may hold validated `Track` display metadata. `MusicAppModel.cachedTrack(for:)` prefers it, then matches the recording ID against the current queue, likes, playlists, recents, events and mixes. A playable legacy file without matching metadata gets the explicit **Cached song** fallback. Inventory browsing neither fetches replacement catalog metadata nor adds listening recents.

The model owns coalesced `refreshCachedSongs()` work and exposes inventory, usage, playable IDs and error/loading state. Removal invalidates older reads before publishing its outcome. `removeCachedSong(id:)` serializes with cache clearing/limit changes, drains writers/preparation and rechecks live pins before deleting every variant. `removed`, `notFound`, `inUse` and thrown failure remain distinct. Current, standby, next-automatic and outgoing files are protected even while paused.

`ConnectivityMonitor` maps `NWPathMonitor` to unknown/online/offline and exposes a thread-safe offline snapshot to the resolver. Unknown is not proof of provider reachability. Known offline retires remote resolution, prefetch and automatic discovery/radio work while keeping local navigation and saved-metadata Search usable. Cached Songs substitutes artwork placeholders offline; audio, lyrics and artwork have independent availability.

Normal resolution and forced retries use cached audio before checking the network, including after relaunch. An unexpired in-memory media URL is not an offline file. Explicit best-quality reload requests fresh extraction only when not known offline; its UI control is disabled offline. Active remote playback can hand off to a complete local copy at the current position without adding a second track start. Reconnection can resume preparation for an unchanged playing pair, but does not start paused playback or replay an exhausted queue.

`OfflineQueueNavigation.advancing` checks at most the queue's occurrence count, skipping uncached entries while preserving order, duplicate occurrences and repeat behavior. Native Next/end obtains fresh inventory and rejects late results after a newer playback intent. Unknown/failed inventory and known exhaustion have different errors. Offline traversal does not rewrite the queue or request Autoplay. Derived retention and the no-TTL audio policy are in [LISTENING_DISCOVERY.md](LISTENING_DISCOVERY.md#cache-retention-from-listening).

### Saving the remaining queue

[`QueuePlaylistSnapshot(queue:currentIndex:)`](../Sources/Core/QueuePlaylistSnapshot.swift) returns current-plus-upcoming tracks from the visible order, deduplicating recording IDs only after slicing. Invalid indices yield an empty selection. Queue's `queue.saveRemaining` action captures this once into a `UserPlaylist` draft before opening `PlayerQueuePlaylistSheet`; subsequent playback, queue edits and radio continuation cannot alter the draft.

The sheet uses the atomic playlist API and confirms durable publication before showing success. A failed write keeps the name/selection and offers library reload when required. Save neither replaces the active queue nor changes audio position, shuffle or repeat. The actual queue retains duplicate occurrence identities. [R6 test coverage](LISTENING_DISCOVERY.md#test-coverage) links the unit, native-player and UI cases.

### Opus preparation, cache variants, and reload

`OpusNativeAudio.isSupported` enables the Opus path only on **iOS 26.5+**. Older systems select AAC. The resolver ranks eligible source encodings before checking URL usability and keeps AAC candidates for fallback. A challenged best tier reaches full extraction rather than silently selecting a lower clear tier. Each Opus candidate requires a complete local download and prepared MP4; AVPlayer is never given the original WebM as this path's playable file.

`OpusRemuxer.remux(input:output:timeout:)` invokes the synchronous `gb_remux_opus` C bridge off the main actor. FFmpeg copies encoded Opus packets into MP4 without re-encoding, decoding, or network I/O. `OpusNativeAudio.inspect(_:)` requires one Opus audio track, no video, 48 kHz mono/stereo, a usable duration, and an actual nonempty PCM sample from AVAssetReader. This is per-file native validation, not a claim that every sample is decoded before playback.

| Operation | Default bound |
| --- | --- |
| Resolver Opus acquisition/preparation attempt | 12 seconds |
| App remux interrupt callback | 10 seconds; the underlying C bridge also has its independent 30-second ceiling |
| Explicit quality reload | Up to 60 seconds for resolution |
| Input/output preparation files | 64 MiB each; reserve 128 MiB of cache headroom before preparation |

Timeouts/cancellation retire the work and prevent publication; preparation owns its files until native work unwinds. A failed Opus attempt falls back to AAC and has a bounded per-recording cooldown. Explicit reload clears that recording's cooldown.

`AudioCache.storeOpus` writes a fresh immutable `<trackID>.opus-<UUID>.m4a` and atomic sidecar with `opusPreparationVersion: 1`. It preserves the existing encoding and protects every variant of an in-use logical song. Up to two prepared Opus variants are retained; unavailable space or a protected variant limit causes fallback rather than overwriting a live file. Rejection can target one variant through `rejectPlaybackFile(_:)`.

`entry(for:allowOpus:)` chooses the best compatible committed encoding for the logical ID. Consequently, a successful quality reload can add a higher-quality prepared variant that **later ordinary plays reuse**. The reload does not mutate the original file, set a persistent user bitrate preference, or reprocess the entire library.

`AudioCache.Usage.bytes` sums all committed encodings plus bytes present in active preparation files. `songCount` counts distinct logical recording IDs; preparation bytes do not create an extra song. Retained bytes include all committed variants of retained IDs. Sidecars and abandoned partial files are excluded from that media-byte total. Cache limits and privacy behavior are in [PROVIDERS.md](PROVIDERS.md#audio-cache-and-quality).

## Companion interfaces

`GanaBajanaApp.init()` creates one `CompanionPlaybackController` around the selected `MusicAppModel` and installs it in `CompanionRuntime.playback` before scenes connect. Normal launches retain and start `WatchPhoneSession` with that instance. Test launches skip real WatchConnectivity except for the explicit DEBUG paired fixture: `DebugBootstrap.usesPairedWatchFixture` requires all three flags `--uitesting --seed-ui --ui-watch-connectivity`. ### Shared controller and wire contract

`CompanionPlaybackController.handle(_:)` validates requests and their encoded size, then routes actions through the existing model/player/library APIs. Library pages contain at most 40 rows from Favorites, Recently played, Playlists, individual playlists, or Queue. `.playItem` carries the page location, opaque occurrence ID, and revision of the complete ordering. A stale revision is rejected rather than selecting a song at a reused index; queue selection uses `MusicAppModel.playQueueTrack(at:)`.

The controller retains up to 128 request receipts in memory. Replaying the same request ID, version, action, and expected track ID returns the cached response without repeating the action; reusing an ID for another command is rejected. Lease renewal does not change command identity. This idempotency applies only while the receipt remains in that controller's bounded window, not across eviction or process restart. An accepted response confirms synchronous phone handling, not completed media preparation or audible output. Library failures can coexist with changed playback and use `snapshot.libraryError`, separately from `nowPlaying.errorMessage`.

`CompanionWire` limits each encoded request, reply, and snapshot to **60 KiB**, checked after encoding and before decoding. WatchConnectivity uses this codec directly; CarPlay passes the shared values in process. Payloads contain recording/control metadata and library rows, without audio, media URLs, account cookies, or artwork assets. Snapshot sequences order state within a phone-process session.

A lease also records the repeat mode returned in its snapshot. Before the first repeat-mode cycle, the controller rejects a leased change if the phone's mode has changed since that snapshot. Further cycles belong to the same command. An already-satisfied desired mode remains a no-op but still requires an unexpired lease; receipt replay never overwrites a newer phone choice.

### Native Apple Watch companion

`project.yml` defines `GanaBajanaWatch`, a watchOS 11+ app embedded in the iPhone app, with bundle ID `com.agraabhi.ganabajana.watchkitapp` and `WKRunsIndependentlyOfCompanionApp: false`. Its entry point and Leafnote icon are configured. It shares only the Foundation companion contract from the phone's Core directory. The Watch has no catalog, authentication, extraction, or audio-player dependency. Native views expose play/pause, previous/next, favorite, shuffle/repeat, and library/queue selection; audio plays through the iPhone's selected route. Primary transport controls precede progress, with first-viewport visibility verified in the paused 40 mm fixture before scrolling.

Interactive Watch requests use `sendMessageData` with correlated replies. Mutations first obtain a fresh phone-issued execution lease through a read-only snapshot preflight. `WatchPhoneSession` rejects lease-less mutations. The controller checks the lease's session and **6-second lifetime on the phone's monotonic clock immediately before mutation**, including after page validation. The Watch rechecks the displayed track and relevant control state before dispatch.

The preflight has its own **8-second deadline**; the mutation's separate **8-second deadline starts when sent, after lease issuance**. The full interaction can therefore exceed eight seconds. The phone also has an independent 6-second receiver/reply deadline. These are Watch transport rules; local CarPlay requests leave the optional lease nil. There is one Watch mutation slot across preflight/dispatch and no queued playback-intent transport. After an ambiguous dispatched result, the client refreshes phone state instead of retrying the mutation. Cancellation after dispatch cannot recall a command still within its lease.

Background application context contains only `breezy.snapshot.v1: Data`. Activation or context delivery never executes a playback command. Track, duration, transport/settings, and library-error changes attempt immediate publication when the session can publish, including while the Watch is unreachable. Pure position updates are coalesced to at most once per **10 seconds** while reachable, with the latest trailing snapshot retained; **no pure-position updates are sent while unreachable**. WatchConnectivity determines actual delivery timing.

The Watch interpolates elapsed time from its monotonic receipt clock only for confirmed, reachable, foreground playback that is playing without loading or a playback error. It freezes on disconnection/backgrounding and requires a fresh reply after reconnecting; offline time is not added. Unconfirmed state is labeled **Last seen on iPhone** with playback actions disabled. [WATCH.md](WATCH.md) owns heartbeat/freshness bounds, callback ordering, and paired-device acceptance details.
