# Velvet Thorn implementation contracts

## Product and identity

Velvet Thorn is a native iPhone and iPad streaming player for iOS 18+, with listening-led discovery, unrestricted Search, radio, lyrics and a local library. It runs on Apple silicon Macs as an iPad app (Designed for iPad); Mac Catalyst is not available because FFmpegBridge ships iOS slices only. Native watchOS 11+ and CarPlay interfaces control the same player. The selected name is `Breezy - Stream Music & Chill`; the Home Screen displays `Breezy`. Project/module/scheme `GanaBajana`, bundle ID `com.agraabhi.ganabajana`, URL scheme `ganabajana`, and `Application Support/GanaBajana` are stable identities.

**Delivered build 6 remains current in App Store Connect.** It was uploaded on 27 September 2026, processed VALID and attached to the iOS draft. Its receipts and input hashes are frozen. [APPSTORE_TESTFLIGHT.md](APPSTORE_TESTFLIGHT.md) owns remote facts; [VERIFICATION.md](VERIFICATION.md) owns execution evidence.

Local R19 source is `1.0.0 (9)`, uncommitted. It carries the integrated R18 features and export corrections plus the super-like tier and motion polish ([SUPER_LIKES.md](SUPER_LIKES.md)); R18 verification is in progress. Earlier build-7 R17 checks retain their completed scope. No R19 commit, push or upload is authorized or performed. [ROADMAP.md](ROADMAP.md) owns round status.

Recording-language/duration metadata uses the official YouTube Data API; the music catalog and extraction/caching integration remain unofficial, with the content-rights hold recorded in release status. These contracts describe source behavior. Native two-device iCloud, physical paired-Watch/CarPlay behavior, actual AirPlay receivers and hardware acceptance remain separate from fixture checks.

Current source includes visible **Stats**, title-cased app headings/actions, the shared Download Liked Songs scope menu, slice observation and async listening checkpoints. [SCROLLING_PERFORMANCE.md](SCROLLING_PERFORMANCE.md) records the R16 architecture, coordinator-measured timings and coverage limits. The coordinator owns run counts in [VERIFICATION.md](VERIFICATION.md); earlier receipts retain their original scope.

## Shared models

- `LiveRadioStation` is a distinct station value, not a `Track`, `MusicSource` or song Search selection. `ResolvedStream.playbackSource` is actual byte-provider provenance, independent of catalog identity; `extractionGeneration` is optional memory-only evidence. Neither adds a second catalog identity to `Track`.

- `Track.credits: [ArtistCredit]` holds provider-order artist names and optional IDs. `artists`/`artistID` are derived; legacy stored tracks decode into credits. `Track.allCredits` adds artists named in title feature clauses. `CatalogPage.credits` carries album-header credits.
- `ArtistPage.monthlyAudience` retains the provider metric, numeric value, and raw display text. A listener count is not a monthly play count. Recording counts stay attached to recording IDs.
- `HomeLayoutPreferences` stores section order and hidden identifiers, preserving unknown identifiers across decoding. `UserPreferences` includes `homeLayout`, `accent`, `audioCacheLimit` and five independent `languageNudges` fields alongside playback, legacy discovery, DNS and history choices. `LanguageRecommendationNudge` has `automatic`, `more` and `less`; missing fields decode as Automatic. The R12/R13 fields `trailingTimeStyle` (`.songLength` default), `playerSwipeUpAction` (`.lyrics`), `audioQuality` (`.best`), `equalizer` (`EqualizerSettings()`), `downloadsOverCellular` (false), `autoDownloadLikedSongs` (false), `enabledCatalogSources` (`MusicSource.allCases`, ordered) and `sponsorBlockSkipping` (false), plus `genreNudges` (`GenreNudges()`) and R19's `autoDownloadSuperLikedSongs` (false), decode leniently: an unreadable value falls back to the default instead of blocking the file. The derived `autoDownloadScope: AutoDownloadScope` (`off`, `superLiked`, `liked`) reads the two download leaves (All Liked wins) and its setter writes both. `LibrarySyncPreferences` flattens nested preferences into leaf registers (`equalizer/isEnabled`, `equalizer/preset`, `equalizer/gains`, `equalizer/preamp`, `genreNudges/<family>`); `enabledCatalogSources` is one ordered leaf.
- `MusicSource` (`youTubeMusic` = bare ids, `jioSaavn` = `saavn:`, `gaana` = `gaana:`) supplies `source(of:)`, `providerID(of:)`, `trackID(forProviderID:)`, `collectionID(_:providerID:)` (`saavn:album:`, `saavn:playlist:`, `saavn:artist:` and the `gaana:` forms; YouTube collections keep their bare browse ids), `entityKind(of:)` (nil for bare ids) and `entityProviderID(of:)`. `Track.source`, `Track.providerID`, `Track.shareURL` and `MusicCollection.source` derive from the id. Provider ids are validated as short URL-safe tokens or decimals before they become an id. Bare 11-character ids keep every existing path.
- `TrackDetails` (`Sources/Core/TrackDetails.swift`) is the Codable Song details model: recording id, title, performers, `Credit { role: CreditRole, names }`, album, release date and text, ℗/© lines, channel, published date, description (clipped to 16 KiB), view count, ISRC, MusicBrainz id, sources and fetched date; `displayCredits`, `labelNames`, `creditSource`, `hasContent`, `fillMissing(from:)`, `addCredit`, `trimmedDescription`. `CreditRole` covers composer, lyricist, producer, arranger, publisher, label, mixing/mastering/recording engineer, vocals and `other(String)`.
- `EqualizerSettings` (`isEnabled`, `preset`, `gains`, `preamp`, `effectiveGains`, `resolvedPreamp`, `isFlat`, `summary`, `setGain(_:band:)`, `reset()`) decodes leniently with exactly ten clamped gains in `-12...12` dB. `EqualizerPreset` lists Flat, Bass boost, Bass reducer, Treble boost, Vocal, Rock, Pop, Jazz, Electronic, Acoustic, Loudness and Custom with `bandFrequencies` at ISO octave centres from 31.25 Hz to 16 kHz. `AudioQualityPreference` (`best`, `balanced`, `dataSaver`) exposes `title`, `detail` and `maximumBitRate` (nil, 160,000, 64,000).
- `ShuffleStyle.random/fewerRepeats` and `DiscoveryFamiliarity.familiar/balanced/newMusic` are independent scalar preferences. New/missing values default to Fewer repeats/Balanced; present invalid values fail decoding. Every stored Random is preserved, regardless of `shuffleDefaultMigrated`. That leaf remains Codable/synced for compatibility; `migrateShuffleDefault()` returns false without mutation. Explicit choices use `chooseShuffleStyle(_:)` through `updatePreferences`. Legacy v1/v2 shuffle tombstones keep Random, and sparse journals need no synthetic revisions. [SETTINGS.md](SETTINGS.md#shuffle-default-r14-item-12) and [ICLOUD_SYNC.md](ICLOUD_SYNC.md) own preservation; [Listening controls](LISTENING_DISCOVERY.md) owns weighting and metrics.
- `RadioSeed.song(Track)` / `.artist(ArtistCredit)` and `RadioTuning` describe the current generated Radio. `SeedRadioEngine` returns original anchors and bounded recommendation batches; MusicAppModel owns session/intent fences, and PlayerController owns occurrence-safe queue mutation. `RadioHistoryStore` persists 20 seed/tuning entries outside library sync, guarded by the library history epoch. Persisted queues restore paused without an active radio session. Legacy `RadioConfiguration`, `RadioExperience` and `RadioSetupView` remain for compatibility only. [SEED_RADIO.md](SEED_RADIO.md) owns the current contracts.
- `ArtistSongLanguageResult` distinguishes identified, likely, and unclassified results with provenance. Only identified results participate in language-specific filters; weak suggestions remain unclassified for filtering. Library overrides take priority over automatic evidence.
- `LyricsDocument` distinguishes synced, plain, instrumental, and unavailable content. A thrown lookup error is not an unavailable document. `LyricsRequestKey` includes recording ID and metadata so dubbed recordings cannot share a lyrics result accidentally.
- `AlbumDescription` retains the album ID/title/credits, supplied prose, Wikipedia article URL, supplied license and its URL, and excerpt status. `CatalogPage.albumDescription` is optional and defaulted; existing catalog implementations need not supply it.
- `SearchSelection` is `.track(Track)` or `.collection(MusicCollection)`. Identity includes the case-sensitive provider ID and collection kind, not title. A persisted collection selection has no track payload. `CachedSong`, `AudioCacheSnapshot` and `AudioCacheRemoval` project existing cache files rather than create a second library or downloader.
- `SourceAudioQuality: Codable, Equatable, Sendable` holds AAC-family or Opus codec metadata with optional bitrate, sample rate, and channels. `preferredBitRate(average:advertised:)` uses valid average bitrate first; `prefers(_:over:)` orders encodings by that value and prefers AAC on ties. `ranked(_:maximumBitRate:quality:)` orders any candidate type under an optional ceiling: fitting formats first in `prefers` order, then the non-fitting formats in ascending order (lowest first, AAC before Opus on ties), unknown bitrates last; `fits(_:maximumBitRate:)` never blocks on an absent ceiling or unknown bitrate. This is a selection rule, not perceptual equivalence between codecs. `ResolvedStream.quality` and cache sidecars carry metadata without signed URLs; missing optional quality leaves legacy AAC entries usable.

Concrete providers:

- `YouTubeMusicService: MusicCatalogProviding, LyricsProviding, AlbumDescriptionProviding` has defaulted `session` and `now` injection. Its lyrics method follows the selected recording's Lyrics-tab browse ID and returns plain text. `audioMetadata(for:)` batch-validates album-audio metadata. Ordinary album browsing carries a parsed description; `albumDescription(id:)` optionally reads only the first browse header through the same transport/cache. `browsePage` confirms only credits-linked candidates through `get_queue` and rebuilds a playlist page one recording per row in the provider's order: a confirmed album recording replaces its clip in place and a replaced clip does not reappear; video entries list as themselves without a round trip.
- `CatalogParser.RowContext.keepsVideoRows` is true for `VL…` playlist ids, including continuation pages, and false for search, radio, artist and album contexts; with it `track` accepts `MUSIC_VIDEO_TYPE_OMV`, `UGC` and `OFFICIAL_SOURCE_MUSIC` rows as `isAudioRecording == false`, while podcast-typed, greyed-out and playback-type-less rows stay out. `browseRowCandidates(_:inheriting:)` returns one ordered candidate list per row (a confirmed row is itself; otherwise the `MPTC` credits-linked recording first and the row's own video entry second); `audioCandidateIDs` keeps the audio-only view. `browse(_:context:)` is the entry point with a caller-fixed context that the account import uses for liked songs and history. `CatalogDiscovery.accepts`, `ExperienceRadioEngine.isUsable`, `RecommendationEngine.isRecommendable`, `AutoplayContinuation`, `YouTubeDataAPI`, `ArtistSpotlightMusicBrainz` and both prefetch paths still skip video entries. [PLAYLIST_BROWSE_FIX.md](PLAYLIST_BROWSE_FIX.md) records the evidence.
- `YouTubeChartsService: MusicChartsProviding` selects weekly `TRACKS` entries with album-audio counterparts. Original ranks, dates, and region remain in the result.
- `YouTubeDataAPI.recordingLanguage(for:)` reads only exact-recording `snippet.defaultAudioLanguage`; `prepareForLookup(_:)` fills a missing duration in a temporary track copy. Known valid durations and saved metadata are preserved. `metadata(for:refresh:)` returns `Metadata` with `description`, `channelTitle`, `publishedAt` and `viewCount` from the same one-unit request (`requestedParts`, `requestedFields` name the projection); `refresh` skips one cache read and recaches. [YOUTUBE_DATA_API.md](YOUTUBE_DATA_API.md) owns request fields, credential restrictions, cache/deadline/backoff limits, metrics and verification.
- `LRCLyricsService` and `CompositeLyricsProvider` retain baseline matching/fallback and add `LyricsVariantsProviding`. Production installs `JioSaavnLyricsProvider(catalog: sources.saavn)` through `additionalVariantSource`. Strict matching, deadlines and memory-only selection are owned by [LYRICS_VARIANTS.md](LYRICS_VARIANTS.md). An instrumental baseline ends discovery.
- `ArtistSpotlightLanguageService.classification(for:)` reuses verified recording metadata and cached evidence, then checks `recordingMetadataLookup` before lyrics or recognition. Explicit audio-language results skip classification; absent/failed metadata keeps the concurrent lyrics and optional MusicBrainz path inside the original overall deadline. `Configuration.sourceTimeout` bounds each fallback source; `recordingMetadataTimeout` bounds the initial lookup. `ArtistSpotlightMusicBrainz.shared` requires the HTTPS `MusicBrainzContactURL` configured in `project.yml`. Its recording and conditional exact-work lookups share one rate limiter and provider deadline. [PROVIDERS.md](PROVIDERS.md#radio-and-language-evidence) owns those bounds.
- `YouTubeStreamResolver: StreamCacheManaging` has `init(allowRemoteFallback: Bool = false, isOffline: @escaping @Sendable () -> Bool = { false })` and an injected initializer with `qualityExtract`, `opusEnabled` and `opusTimeout`. Normal and forced resolution try compatible complete cached audio before requiring a network path. `refreshQuality(track:) async throws -> ResolvedStream` bypasses audio-cache selection only while not known offline, retaining a cached fallback after failure. `setAudioQualityPreference(_:)` stores the ceiling, retires signed-URL cache entries above the new ceiling or chosen under a tighter one (entries are tagged with the ceiling they were chosen under), and cancels speculative warmups; `validated` ranks every candidate list with the ceiling captured when the flight started, and the production fast path is `CappedFastExtraction` (`YouTubeAudioFastPath.extract(videoID:maximumBitRate:)`, `audioResult(in:videoID:allowOpus:maximumBitRate:)`). `resolve` and `download` throw `invalidID` for any id whose `track.source` is not YouTube Music.

`StreamCaching` extends resolution with `download(_:)`, `discardCached(_:)`, variant-specific `discardCached(_:url:)`, `retainCached(_:)`, and `isCachedStream(_:)`. `StreamCacheManaging` adds `audioCacheUsage()`, `audioCacheSnapshot()`, `removeCachedSong(id:retaining:)`, `updateCacheListeningHistory(_:now:)`, clearing and cache-limit APIs. Optional inventory/removal defaults return nil, not a verified empty cache or successful deletion. Other resolvers need not own a production cache.

`URLSession.boundedData(for:maximumBytes:delegate:)` checks declared and incrementally received body size before returning data. Its optional task delegate lets the Data API refuse redirects before forwarding the credential. Early exit and caller cancellation cancel that request's task; HTTP status and payload validation remain caller-owned. The vendored extraction transport applies its own request budgets and cancellation, and concurrent player lookups use structured task groups. ### Composite catalog and stream routing

`CompositeCatalog` (actor, `Sources/Catalog/CompositeCatalog.swift`) implements `MusicCatalogProviding`, `LyricsProviding` and `AlbumDescriptionProviding` over one YouTube Music primary and optional JioSaavn and Gaana services. `search` fans out to every enabled source only inside `searchingAllSources { }`, which `MusicAppModel.loadSearch` sets; every other search is a plain YouTube Music pass-through so internal lookups (name-only credits, radio seeds, spotlight counts, artist artwork, release checks) never mix providers. Merged results list YouTube Music first, then each further source under its own section; a source that fails or exceeds the six-second secondary deadline is dropped and only the primary's error surfaces when every source fails. `browse`, `artist`, `radio`, `recommendations`, `lyrics` and `albumDescription` route by `MusicSource.source(of:)`; a prefix without an installed provider answers empty for search, radio and lyrics and "not available in this build" for browse and artist (`EmptyCatalog`). `setEnabledSources` and `activeSources` follow `enabledCatalogSources`; YouTube Music is always active.

`CompositeStreamResolver` (struct, `init(youTube:saavn:gaana:audioCache:isOffline:)`) implements `StreamCacheManaging` and `PlaybackConfigurableResolving`. Prefixed ids check the shared `AudioCache` for a complete local copy first, then route to `JioSaavnStreamResolver` or `GaanaStreamResolver`; bare ids go to `YouTubeStreamResolver`, which also owns the cache surface (`audioCacheUsage`, `audioCacheSnapshot`, removal and limits). `download(_:)` stores single-file prefixed streams through `AudioCache.store(trackID:from:stream:permit:track:)` as `saavn~<id>` / `gaana~<id>` and refuses HLS playlists (`isCacheable`, `event=cache_skipped source=gaana reason=hls`); `discardCached` and `isCachedStream` cover prefixed keys; `setNetworkOffline` mirrors the player's flag for prefixed sources; `setAudioQualityPreference` forwards the ceiling to every resolver. `MusicAppModel.ProductionSources` builds one `YouTubeMusicService`, `JioSaavnCatalogService` and `GaanaCatalogService` shared by `makeProductionCatalog` and `makeProductionResolver`.

`JioSaavnCatalogService` (actor) also conforms to `LyricsProviding` (plain `lyrics.getLyrics` text, attribution "JioSaavn") and answers `discovery` with `[]` and `albumDescription` with nil. `JioSaavnStreamResolver` decrypts `encrypted_media_url` (DES-ECB, key `38346591`, `JioSaavnMediaURL`), selects the tier under the ceiling (320 only when the row's `320kbps` flag is true, then 160, 96, 48), probes it with `Range: bytes=0-1023`, and joins concurrent resolutions of one song. `GaanaCatalogService` (actor) is not a `LyricsProviding`; its `radio(seed:)` is the seed's first credited artist's popular songs. `GaanaStreamResolver` (`init(catalog:fallbacks:quality:probe:now:cacheCapacity:)`) decrypts `urls.<tier>.message` (AES-128-CBC, `GaanaMediaURL`), selects `high` or `medium` under the ceiling, probes the HLS master, and asks its `CrossSourceStreamFallback`s (JioSaavn, then YouTube Music) when Gaana hands out no stream. Both resolvers keep 24-song memory URL caches cleared when the ceiling changes and persist nothing decrypted. [JIOSAAVN.md](JIOSAAVN.md) and [GAANA.md](GAANA.md) own endpoints, bounds, parsers and metrics.

### Song details

`TrackDetailsService` (actor, `TrackDetailsFetching`) reads the "Provided to YouTube" description first (`ProvidedToYouTubeDescriptionParser.parse(_:)`, pure), through `YouTubeDataAPI.metadata(for:refresh:)` or, when the Data API cannot answer, `YouTubePlayerDetailsClient.details(for:refresh:)` (cookie-free WEB `player` request; 8 s, 1 MiB, two concurrent, coalesced, 32-entry 15-minute memory cache, `Retry-After` and 15 to 60 s backoff). MusicBrainz fills gaps through `ArtistSpotlightMusicBrainz.recordingDetails(for:)` (`MusicBrainzRecordingDetails`; search, `recording/<id>?inc=recordingDetailsInc`, then one follow-up `work/<id>?inc=artist-rels` or `release/<id>?inc=labels`; at most three requests within 12 s, ambiguity gives up after one request). Description facts win (`TrackDetails.fillMissing`); performers are always `track.allCredits`; only YouTube ids get YouTube requests. `TrackDetailsStore` (actor, `TrackDetailsProviding`) caches 64 entries in memory, 500 JSON files under `Caches/Details/<sanitised id>.json` (`fileName(for:)`, `fileURL(for:in:)`, `enforceFileLimit`, `defaultDirectory()`), remembers recordings without facts for 15 minutes in memory only, bypasses caches on `refresh` while keeping shown facts when a refresh finds nothing, and answers offline from files without any request. `PlayerSongDetailsView` is `PlayerOptionsRoute.details` inside the More sheet's navigation stack.

### SponsorBlock skipping

`SponsorBlockClient` (actor, `SponsorBlockSegmentProviding`) sends `hashPrefix(for:)` (first four hex characters of SHA-256 over the video id) to `sponsor.ajay.app/api/skipSegments/<prefix>` with the requested categories and `actionTypes=["skip"]`, parses only the matching `videoID`, and caches per video id (24 h positive, 1 h negative, 256-id LRU) with `Configuration` bounds (6 s, 256 KiB, two concurrent, `RequestError.busy` for a third caller). `SponsorBlockSegments.usable(_:duration:)` filters and merges submissions (skip action, votes >= 0 or locked, >= 1 s, <= 80 percent of the recording, 32 max). `SegmentSkipper` (pure struct: `install`, `restart`, `noteManualSeek(uptime:)`, `skipTarget(at:uptime:)`, `skippedCount`) decides once per play with a 0.25 s end guard and a 10 s manual-seek grace. `PlayerController.setSponsorBlockSkipping(_:)` gates the lookup, which starts only when a YouTube song actually plays (`selectCurrent`, `activateStandby`) and never known offline; `applySegmentSkip(uptime:)` runs at the end of `tick()` and jumps through the ordinary `performSeek` path, so the listening clock treats it as a seek and generation checks still guard the completion. No skip during a crossfade blend or a pending offline advance; the standby deck is never pre-skipped. `sponsorBlockSkipCount` and `sponsorBlockSegments` are observable; segments live in memory only.

The writable `preferences` property commits mutations. Views use `MusicAppModel.updatePreferences(_:)` so dependent services receive only the preferences actually saved. Each commit validates a candidate document, checks the file on disk (an `lstat` stamp of device, inode, size, modification and change time recorded after each load and write; any difference falls back to the full byte comparison), writes atomically, and publishes state only after success. Unreadable/future stores block writes. A stale writer cannot replace an externally changed library.

Views never call `toggleFavorite` or `setSuperLiked` directly. `MusicAppModel.toggleLike(_:surface:)` (like an unliked song; remove a liked or super liked song completely) and `toggleSuperLike(_:surface:)` (not liked or liked becomes super liked; super liked steps back to liked) with `LikeSurface { player, menu, more, library }` are the only view entry points. [SUPER_LIKES.md](SUPER_LIKES.md) owns the tier.

`document` is `@ObservationIgnored`. Observable getters read process-local slice revisions, with `historyRevision` and `recordingLanguageOverridesRevision` available to projection caches. Publication installs the durable document and favorite/dislike indexes before changing revisions. Playback-only commits do not invalidate preference/history readers; failed writes publish no data revisions. Reload/cloud adoption also publish by changed slice, including metadata replacements with unchanged counts/totals. These revisions never enter the saved format or sync journal.

Async player checkpoints capture immutable document/events/recents/snapshot state on the main actor. `LibraryListeningCheckpointPreparation.make` runs detached at utility priority: full candidate validation, retention, targeted journal projection and encoding. Apply checks cancellation and document/privacy/context generations before the disk-baseline check and atomic write in a non-suspending main-actor turn. The journal and document become durable together. Manual mutations and compatibility callbacks remain synchronous. One library preparation is admitted at a time, with at most three preparation/rebase attempts per call; stale playback/recent captures are omitted rather than replacing newer intent. `recordListeningCheckpoint` acknowledges durable success or an applicable no-op; the lower-level `applyListeningCheckpoint` Bool instead reports whether bytes changed.

Playlist creation saves the trimmed name and recording-ID-deduplicated tracks in one commit, including the sync journal. The returned UUID alone is not a success acknowledgement: Queue Save checks that it exists in `playlists` and `errorMessage == nil`. Invalid metadata or a failed write publishes neither an empty placeholder nor a partial playlist.

`recentSearchSelections` holds at most 20 explicit destination selections, newest first. Reopening an item advances its revision even if it was already first locally. Collection tracks are stripped before validation/persistence. Legacy query strings remain in `recentSearches`, with no guessed conversion to entities. `clearRecentSearches()` atomically clears both fields and advances `searchReset`, including when already empty. Listening-history disable/clear is an independent boundary. [ICLOUD_SYNC.md](ICLOUD_SYNC.md) owns typed floors, revisions and schema compatibility.

Listening updates are delta seconds. A true acknowledgement means the delta was durably saved, or was an applicable no-op. `PlaybackListeningBuffer` retains unacknowledged deltas for up to 128 original session identities; async batches share that bound and a delivery makes at most three captures. Delivery subtracts the exact acknowledged seconds, preserving newer seconds accumulated during the await. Cancellation after commit must still consume the durable acknowledgement. Capacity exhaustion pauses playback instead of dropping pending time. The buffer is memory-only and does not survive termination.

Clearing history or successfully disabling history changes the persisted privacy epoch. Both enabled-to-disabled and disabled-to-enabled preference changes retire captured delivery and reset the player's listening clock only after durability; failed preference changes preserve pending work. Re-enabling cannot backfill disabled time. Clear removes events, recents and generated mixes, preserving explicit library choices, queue, searches and tips. It retires pending events/recents while automatically retrying a dirty paused resume snapshot as snapshot-only, without another flush. Failed recovery stops and keeps the snapshot retryable. `LibraryRecovery.crossesHistoryBoundary` also recognizes conservative legacy signals such as removed/reduced retained history. Privacy/context fences prevent stale history resurrection; ordinary account/reload retirement keeps eligible unsaved deltas for retry. [SCROLLING_PERFORMANCE.md](SCROLLING_PERFORMANCE.md) owns the focused privacy tests.

`reloadFromDisk()` validates and rechecks the bytes before adopting them, without itself writing a replacement. It returns `.reloaded`, `.historyBoundary`, or `.failed`; failure preserves the established document and blocks writes. `reloadSavedLibrary()` runs outside listening callbacks, retires stale personalization/radio work, reconciles playback/cache/DNS preferences, and then retries eligible buffered listening. A live queue takes precedence over a saved snapshot. Only an untouched failed-startup placeholder receives the recovered queue, restored paused. Lifecycle and restore-retirement callbacks cannot write that placeholder over repaired disk state. [PROVIDERS.md](PROVIDERS.md#local-data-and-backups) owns retention and backups.

### Cached inventory and offline playback

`AudioCache.snapshot(allowOpus:)` groups complete sidecar/media pairs by recording ID, checks file size/type and selects an eligible encoding. `CachedSong.isPlayable` requires a provider recording ID and a compatible preferred local file. Unsupported encodings can remain visible as nonplayable storage; partial files never become song entries. This inventory does not fully decode AAC or establish that every byte will play. `preparedEntry(for:allowOpus:)` uses a native duration read when sidecar duration is missing, with a reader lease retained until native work unwinds. Playback can reject a damaged variant and try another local copy.

New audio sidecars may hold validated `Track` display metadata. `MusicAppModel.cachedTrack(for:)` prefers it, then matches the recording ID against the current queue, likes, playlists, recents, events and mixes. A playable legacy file without matching metadata gets the explicit **Cached song** fallback. Inventory browsing neither fetches replacement catalog metadata nor adds listening recents.

R18 stores actual acquisition provenance in optional `AudioCache.Sidecar.playbackSource`. `CachedAudio.stream`, tier moves and URL-free background-plan metadata retain that provider without changing the catalog recording ID. Absent or unreadable legacy provenance stays unknown; neither catalog identity nor a signed URL supplies it. Active installation and standby activation copy the accepted stream's value into `PlayerController.playbackSource` for More. Complete files have nil `extractionGeneration` and cannot confirm extractor rules. [AUDIO_QUALITY.md](AUDIO_QUALITY.md#r18-playback-provider-provenance) owns the detailed persistence/display and test contracts.

The model owns coalesced `refreshCachedSongs()` work and exposes inventory, usage, playable IDs and error/loading state. Removal invalidates older reads before publishing its outcome. `removeCachedSong(id:)` serializes with cache clearing/limit changes, drains writers/preparation and rechecks live pins before deleting every variant. `removed`, `notFound`, `inUse` and thrown failure remain distinct. Current, standby, next-automatic and outgoing files are protected even while paused.

`ConnectivityMonitor` maps `NWPathMonitor` to unknown/online/offline and exposes a thread-safe offline snapshot to the resolver. Unknown is not proof of provider reachability. Known offline retires remote resolution, prefetch and automatic discovery/radio work while keeping local navigation and saved-metadata Search usable. Cached Songs substitutes artwork placeholders offline; audio, lyrics and artwork have independent availability.

Normal resolution and forced retries use cached audio before checking the network, including after relaunch. An unexpired in-memory media URL is not an offline file. Explicit best-quality reload requests fresh extraction only when not known offline; its UI control is disabled offline. Active remote playback can hand off to a complete local copy at the current position without adding a second track start. Reconnection can resume preparation for an unchanged playing pair, but does not start paused playback or replay an exhausted queue.

`OfflineQueueNavigation.advancing` checks at most the queue's occurrence count, skipping uncached entries while preserving order, duplicate occurrences and repeat behavior. Native Next/end obtains fresh inventory and rejects late results after a newer playback intent. Unknown/failed inventory and known exhaustion have different errors. Offline traversal does not rewrite the queue or request Autoplay. ### Download tier and audio export

`AudioCache.init(directory:downloadsDirectory:...)` adds a permanent tier under `Application Support/GanaBajana/Downloads` (`defaultDownloadsDirectory`, `isExcludedFromBackup = true`) with the same `<key>.m4a|.wav` media, `<key>.json` sidecar (plus `"downloaded": true`) and `<key>.opus-<UUID>` variants as `Caches/Audio`. `<key>` is `storageKey(for:)`: the recording id with `:` replaced by `~`, so `saavn:abc` is `saavn~abc.m4a`; `trackID(forStorageKey:)` maps back. `isValidTrackID` accepts bare YouTube-alphabet ids and `<source>:<id>` for every `MusicSource` prefix; `isProviderTrackID` keeps the 11-character rule for bare ids only. `promoteToDownloads(_:) -> DownloadTierChange` (`moved(bytes)`, `alreadyThere(bytes)`, `notFound`) writes the target sidecar, renames the media, then removes the source sidecar, moving every complete variant; `demoteToCache(_:)` reverses it; `deleteDownload(_:) -> DownloadDeletion` (`deleted`, `demotedInUse`, `notFound`) demotes a song in use instead of deleting it. `entry(for:)`, `preparedEntry`, `CachedSong.isPlayable`, `OfflineQueueNavigation` and `PlaybackCachePipeline.isCachedStream` treat both tiers alike, preferring the downloaded copy. ### Opus preparation, cache variants, and reload

`OpusNativeAudio.isSupported` enables the Opus path only on **iOS 26.5+**. Older systems select AAC. The resolver ranks eligible source encodings before checking URL usability and keeps AAC candidates for fallback. A challenged best tier reaches full extraction rather than silently selecting a lower clear tier. Each Opus candidate requires a complete local download and prepared MP4; AVPlayer is never given the original WebM as this path's playable file.

`OpusRemuxer.remux(input:output:timeout:)` invokes the synchronous `gb_remux_opus` C bridge off the main actor. FFmpeg copies encoded Opus packets into MP4 without re-encoding, decoding, or network I/O. `OpusNativeAudio.inspect(_:)` requires one Opus audio track, no video, 48 kHz mono/stereo, a usable duration, and an actual nonempty PCM sample from AVAssetReader. This is per-file native validation, not a claim that every sample is decoded before playback.

| Operation | Default bound |
| --- | --- |
| Resolver Opus acquisition/preparation attempt | 12 seconds |
| App remux interrupt callback | 10 seconds; the underlying C bridge also has its independent 30-second ceiling |
| Explicit quality reload | Up to 60 seconds for resolution |
| Input/output preparation files | 64 MiB each; reserve 128 MiB of cache headroom before preparation |

Timeouts/cancellation retire the work and prevent publication; preparation owns its files until native work unwinds. A failed Opus attempt falls back to AAC and has a bounded per-recording cooldown. Explicit reload clears that recording's cooldown.

`AudioCache.storeOpus` writes a fresh immutable `<trackID>.opus-<UUID>.m4a` and atomic sidecar with `opusPreparationVersion: 1`. It preserves the existing encoding and protects every variant of an in-use logical song. Up to two prepared Opus variants are retained; unavailable space or a protected variant limit causes fallback rather than overwriting a live file. Rejection can target one variant through `rejectPlaybackFile(_:)`.

`entry(for:allowOpus:)` chooses the best compatible committed encoding for the logical ID. Consequently, a successful quality reload can add a higher-quality prepared variant that **later ordinary plays reuse**. The reload does not mutate the original file, set a persistent user bitrate preference, or reprocess the entire library.

`AudioCache.Usage.bytes` sums all committed encodings plus bytes present in active preparation files. `songCount` counts distinct logical recording IDs; preparation bytes do not create an extra song. Retained bytes include all committed variants of retained IDs. Sidecars and abandoned partial files are excluded from that media-byte total. Cache limits and privacy behavior are in [PROVIDERS.md](PROVIDERS.md#audio-cache-and-quality).

### Audio quality ceiling

`UserPreferences.audioQuality` reaches the resolver through `MusicAppModel.applyPreferenceServices`, `PlayerController.setAudioQualityPreference(_:)` and `PlaybackConfigurableResolving.setAudioQualityPreference(_:)`, at start and on every change. A change applies to the next resolution; the current song and a standby item already prepared keep their selection. `YouTubeStreamResolver.validated` ranks every candidate list (fast-path streams plus AAC fallbacks, full extraction, AAC fallbacks after a failed extraction) with `SourceAudioQuality.ranked` under the ceiling captured when the flight started, keeps the existing three-per-codec limit and Opus gate, validates only the pick, and when every fitting URL fails climbs through the higher tiers so a broken low tier does not fail the song. `YouTubeAudioFastPath.audioResult(in:videoID:allowOpus:maximumBitRate:)` returns up to three URLs of the best fitting format and three of the best fitting AAC format; a challenged fitting format still sends the song to full extraction rather than an over-ceiling clear URL. `YouTubeExtractionWorker` accepts every AAC and Opus format YouTubeKit returns, including the 256 kbps itags 141 and 774 (`validBitRate` accepts 8 to 1,536 kbps; the vendored `ITag.swift` lists 774). The in-memory signed-URL cache records the ceiling each entry was chosen under; a change drops entries above the new ceiling and entries chosen under a tighter one, keeps Best entries that fit, and cancels speculative warmups and the speculative prefetch download. Complete cached and downloaded copies play whatever their bitrate; `refreshQuality` resolves fresh under the ceiling and never replaces a saved copy with a lower bitrate. `JioSaavnStreamResolver` and `GaanaStreamResolver` read `maximumBitRate` for their own tier tables. [AUDIO_QUALITY.md](AUDIO_QUALITY.md) owns the rules, metrics and coverage.

### Shared Equalizer and Normalization Tap (R18)

`EqualizerTapInstaller` owns one mix/tap per item for EQ and supported gain-up. `PlayerController.install` configures the incoming item before replacement and refreshes attenuation afterward. `StandbyDeck.onConfigureAudio` configures independent gain before replacement/preroll while retaining its separate readiness callback. EQ curves remain shared across decks; gain targets belong to each item.

`PlaybackNormalization.gainDb` converts finite source loudness to at most +6 dB boost. Missing/invalid metadata or Off uses unity. Inside `EqualizerProcessor`, EQ/preamp precedes gain-up and the channel-linked sample limiter; a 20 ms ramp, instant attack at 0.98 full scale and 100 ms release apply. Player volume carries only `min(1, requestedGain)` times the crossfade envelope. The limiter is neither true-peak nor final-crossfade protection. HLS/live gain-up and unsupported PCM bypass; an unrelated audio mix is preserved.

EQ Off leaves a fresh item untapped only when normalization needs no gain-up. Taps can introduce native gapless priming delay; R12 measurements below are historical EQ-only evidence. Render/prepare callbacks log nothing, and `tick()` reports bounded mode/counter changes through the installer. [VOLUME_NORMALISATION.md](VOLUME_NORMALISATION.md) owns current DSP/format bounds and [EQUALIZER.md](EQUALIZER.md) owns presets and profile storage.

### Historical R12 Equalizer Tap

The following paragraph records the original EQ-only architecture before R18. Its enable-only installation, attenuation-only normalization and callback logging describe that earlier source, not the current shared tap above.

`EqualizerTapInstaller` (`Sources/Audio/EqualizerTap.swift`, main actor) registers every item where it is created: `PlayerController.install` for the live deck and `standbyChanged()` right after `StandbyDeck.installIfPossible`, so the tap is in place before preroll. Registration is idempotent per item; an `AVMutableAudioMix` with one `AVMutableAudioMixInputParameters` (first audio track from `AVURLAsset.loadTracks(withMediaType: .audio)`) and an `MTAudioProcessingTap` (PostEffects, Float32 at the decode rate) is installed only while `EqualizerSettings.isEnabled`; `update(_:)` installs it later on registered items when the listener turns the equalizer on and ramps live taps to flat, drains 50 ms and leaves the audio untouched when it is turned off. No track (HLS, unsupported asset), a failed load, a failed tap or a non-Float32 format logs `event=equalizer_bypass reason=<no_audio_track|asset_type|tap_create|tracks_failed|item_released|format>` and the item plays without EQ; playback never depends on the tap. One `EqualizerProcessor` per item (`apply(_:revision:)`, `makeTap()`, `prepare`, `unprepare`, `render`) owns one `BiquadBank` (ten RBJ peaking biquads, Q 1.41, `setTargets`, `snapToTargets`, `process(frames:channelStarts:stride:)`, `magnitudeDb(at:)`); settings cross to the audio thread as a trivially copyable snapshot behind a `Mutex` read with `withLockIfAvailable`, `render` allocates nothing, gains and preamp ramp linearly in dB over 20 ms recomputing coefficients every 32 frames, and bands at or above 45 percent of the sample rate are identities. The preamp applies before the filters; `PlaybackNormalization` and `PlaybackCrossfade` keep writing `AVPlayer.volume` after the tap and neither path touches the other's property. With the preamp at 0 the largest positive band gain is subtracted automatically (single-peak headroom); any nonzero preamp applies exactly as set. Gapless with taps on both decks costs 0.20 to 0.40 s at the swap because AVFoundation primes the tap at play; the untapped path stays under 0.15 s. [EQUALIZER.md](EQUALIZER.md) owns presets, layout, metrics and coverage.

### Shared controller and wire contract

`CompanionPlaybackController.handle(_:)` validates requests and their encoded size, then routes actions through the existing model/player/library APIs. Library pages contain at most 40 rows from Favorites, Recently played, Playlists, individual playlists, or Queue. `.playItem` carries the page location, opaque occurrence ID, and revision of the complete ordering. A stale revision is rejected rather than selecting a song at a reused index; queue selection uses `MusicAppModel.playQueueTrack(at:)`.

The controller retains up to 128 request receipts in memory. Replaying the same request ID, version, action, and expected track ID returns the cached response without repeating the action; reusing an ID for another command is rejected. Lease renewal does not change command identity. This idempotency applies only while the receipt remains in that controller's bounded window, not across eviction or process restart. An accepted response confirms synchronous phone handling, not completed media preparation or audible output. Library failures can coexist with changed playback and use `snapshot.libraryError`, separately from `nowPlaying.errorMessage`.

`CompanionWire` limits each encoded request, reply, and snapshot to **60 KiB**, checked after encoding and before decoding. WatchConnectivity uses this codec directly; CarPlay passes the shared values in process. Payloads contain recording/control metadata and library rows, without audio, media URLs, account cookies, or artwork assets. Snapshot sequences order state within a phone-process session.

A lease also records the repeat mode returned in its snapshot. Before the first repeat-mode cycle, the controller rejects a leased change if the phone's mode has changed since that snapshot. Further cycles belong to the same command. An already-satisfied desired mode remains a no-op but still requires an unexpired lease; receipt replay never overwrites a newer phone choice.

### Account library import

`YouTubeAccountLibraryClient` (actor, `YouTubeAccountLibraryProviding`) sends authenticated WEB_REMIX `POST /youtubei/v1/browse?prettyPrint=false` requests to `music.youtube.com` through its own ephemeral `URLSession` (no cookie storage, no URL cache, two connections per host, 20 s per request and 35 s per resource, 8 MiB body cap, one retry after 350 ms for timeouts, connection loss or 5xx, `Retry-After` honoured, 429 as `rateLimited`, 401/403 or `error.status UNAUTHENTICATED` as `unauthorized` without retry). `YouTubeAccountSession.apply(to:origin:)` adds the YouTube-domain `Cookie` header, `Authorization: SAPISIDHASH`, `X-Origin`, `X-Goog-AuthUser: 0` and `X-Youtube-Bootstrap-Logged-In: true`; `request(browseID:cursor:version:session:now:)` is the testable request shape, and continuations reuse `CatalogContinuation` (scope `account|<browseId>`) with the first page's `visitorData`. Browse ids are `FEmusic_liked_videos` (`CatalogParser.browse(_:context:)` with `keepsVideoRows`), `FEmusic_liked_playlists` (collections filtered to `VL` ids minus `VLLM`/`VLSE`), one `VL…` playlist at a time, `FEmusic_library_corpus_artists` (`YouTubeAccountLibraryParser.artists`, `UC…` and `MPLAUC…` rows) and `FEmusic_history` (day shelves in page order, repeats dropped). No account page is cached; `CatalogTransport` stays account-cookie-free. Bounds: 2,000 likes, 1,000 songs per playlist, 200 playlists, 500 followed artists, 500 history rows kept to 200 unique songs, 60 pages per listing.

`YouTubeLibraryImporter` (`@MainActor @Observable`: `start(_:)`, `run(_:)`, `cancel()`, `loadPlaylists()`, `progress`, `summary`, `needsSignIn`, `remotePlaylists`, `lastImportedAt`, `hasSession`; `YouTubeImportBounds` for tests) runs the selected kinds in order likes, playlists, followed artists, history, one library write per page. Likes go through `LibraryStore.addFavorites` (remote order ahead of local likes; a local dislike wins; liked videos stay `isAudioRecording == false`). Playlists become local `UserPlaylist`s with the remote name, or " (YouTube)" appended on a case-insensitive clash, mapped in the ledger so a later import appends to the same playlist through `merge`; remote removals never remove locally. Followed artists go through `LibraryStore.follow` without a release baseline, so `ReleaseWatcher` announces nothing old. History becomes one "YouTube Music history" playlist in recency order, newest first on re-import, with no `ListeningEvent` or `RecentListen`. Failures are per kind; `unauthorized` stops the remaining kinds and sets `needsSignIn`; Cancel stops between pages and keeps what was applied. `YouTubeImportLedgerStore` writes `Application Support/GanaBajana/youtube-import.json` (`YouTubeImportLedger` version 1: `lastImportedAt`, `playlists` remote id to UUID, `historyPlaylistID`, `lastCounts`) atomically with `completeFileProtectionUntilFirstUserAuthentication` and a 4 MiB read cap, after each kind and again with the date once at least one kind completed; a newer version refuses to load and the page reports it; sign-out leaves it alone. `MusicAppModel.youTubeImport` exposes the importer and `init(youTubeImport:)` lets fixtures inject one. [ACCOUNT_IMPORT.md](ACCOUNT_IMPORT.md) owns headers, fixtures, metrics and coverage.

## Consumable tip transactions

`TipJarService(library:observeTransactions:)` loads the five allowlisted consumables, uses verified StoreKit results, and listens to `Transaction.updates` and `Transaction.unfinished`. The library stores transaction IDs with credited/revoked state before `finish()`. Duplicate deliveries do not increase the count; refund records prevent an old delivery from restoring credit. Unverified or unsaved transactions remain unfinished for recovery. Missing products and partial catalogs remain retryable.
