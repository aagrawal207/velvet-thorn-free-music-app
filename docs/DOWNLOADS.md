# Downloads and audio export

Managed permanent downloads began in R12 and gained one-home storage in R13. R17 integrated background transfers, verified AAC export and All/Liked/Not Liked filtering. R18 integrates actual-provider persistence and export timing/cover/share corrections; verification is in progress. R19 adds the Super Liked filter and the three-way Download Liked Songs scope ([SUPER_LIKES.md](SUPER_LIKES.md)). [VERIFICATION.md](VERIFICATION.md) owns counts and current/historical results. [BACKGROUND_DOWNLOADS.md](BACKGROUND_DOWNLOADS.md), [AUDIO_EXPORT.md](AUDIO_EXPORT.md) and [AUDIO_QUALITY.md](AUDIO_QUALITY.md) own detailed contracts.

## Purpose

`AudioCache` keeps complete songs in the purgeable `Caches/Audio` tier, bounded by `AudioCacheLimit` and scored eviction. Downloads add a second, permanent tier with the same file layout so playback, inventory and export find one logical song regardless of tier. A download is not a second copy: a complete cached file is renamed into the permanent tier, and "Remove download" renames it back. Since WP19 a downloaded song has one home: exactly one file in the download tier, nothing in the cache tier, and the Cached songs screen and the temporary-cache totals no longer show it.

## Behaviour

- **Download a song**: `DownloadManager.background` promotes a complete cached copy offline or asks the existing resolver for a downloadable file plan. The OS background session transfers the file; foreground validation/preparation publishes directly into the permanent tier. Gaana HLS is ineligible; a validated fallback file can be downloaded.
- **One home per song** (WP19): promotion renames the song's best playable variant (highest bitrate, AAC on ties, the download-tier file on equal quality, then the newest) into the download tier and removes every other variant of that logical song in both tiers, for example the AAC original after an Opus variant was prepared. A song in use (pinned, being read, or with an active writer) keeps its files: the removal is recorded as pending and runs as soon as protection ends (unpin, reader lease release, writer completion) or at the next maintenance pass (`clearUnused`, `updatePolicy`, `removeSong`), never skipped forever. Renames still happen for a song in use, as before; only deletions wait.
- **Admission for a downloaded song** is refused or redirected: `store` returns the downloaded file without a transfer even when the download is an Opus variant and the base key is absent; `storeOpus` returns the downloaded file when the requested encoding is not better than it (`event=download_admission outcome=refused`, no transfer). When the requested encoding is better, it is prepared and validated as usual and then adopted into the download tier by the same sidecar-first rename (`event=download_replaced`), the old downloaded file becoming a pending or immediate removal. A copy that finishes after its song was promoted meanwhile is adopted when it is the better encoding and dropped otherwise (`outcome=dropped`); the caller receives the file the song keeps. Prefetch, pipeline downloads and speculative upgrades therefore never leave a cache-tier variant beside a download. `isDownloaded(trackID:)` lets the pipeline skip that work early without an actor hop.
- **Migration**: installs from R12 may hold a downloaded song plus stale cache variants (a later "Reload best available audio" prepared Opus beside a downloaded AAC). The first inventory read of a process gives each such song one home, at most `AudioCache.maximumLoadDedupes` (500) songs per read with the remainder on the next read, and logs `event=cache_dedupe_downloaded removed=<n> bytes=<n> songs=<n>` once per process. The read runs on the `AudioCache` actor, never the main actor, and is idempotent: a later launch finds one home per song and removes nothing. A song in use at that moment is left whole and becomes pending like a fresh promotion.
- **Queue**: existing states remain, with `waitingReason`/`statusTitle` distinguishing connection, foreground resolution, processing and storage waits. Two transfer/preparation slots and three-attempt cycles apply. The v2 queue reads v1 ID lists and saves URL-free operation, retry and acquisition records. Launch reconnects OS tasks before scheduling replacements. A failed library load preserves queued intent. iOS retains request URLs in its task storage; the app queue does not.
- **Wi-Fi only by default**: `UserPreferences.downloadsOverCellular` (default off). `ConnectivityMonitor` publishes `isExpensive` (`NWPath.isExpensive || isConstrained`); on an expensive path items park as `Waiting for Wi-Fi` until the path or the preference changes. Offline items park as `Waiting for a connection`; neither counts as a failed attempt. Promotion of an already complete copy ignores both rules.
- **Albums and playlists**: the collection header's `Download` capsule enqueues every track in order. Its state is derived: `Download`, `Downloading n of m` while any track is queued, `Downloaded` when every track is in the permanent tier. Tapping the last two asks to remove the collection's downloads (queued items cancel, downloaded songs return to the cache).
- **Download Liked Songs**: a three-way scope, `UserPreferences.autoDownloadScope` (`AutoDownloadScope.off`, `.superLiked` "Super Liked Only", `.liked` "All Liked"), derived from the two lenient Bool leaves `autoDownloadLikedSongs` and `autoDownloadSuperLikedSongs` (both default false; the menu writes both). `MusicAppModel.favoritesChanged()` diffs favorites and super likes against the known ids on every favorites change, so every like path including Watch and iCloud merges counts: All Liked enqueues each new like (`event=download_auto_like count=N`), Super Liked Only enqueues each promotion (`event=download_auto_super_like count=N`), Off enqueues nothing. Choosing a scope with a backlog first shows "Download Liked Songs?" or "Download Super Liked Songs?" with that scope's count. Narrowing the scope, unliking and demoting never delete a file.
- **Remove download** (song menu, player More, collection confirmation, Downloads context menu): renames the files back into the cache tier. The song stays playable until ordinary eviction. **Delete** (Downloads screen row, swipe, context menu) removes the bytes; a song currently in use is demoted instead so the player keeps its file.
- **Playback**: `AudioCache.entry(for:)` prefers the downloaded copy over any cached variant; `preparedEntry`, the resolver's complete-local-copy path, `CachedSong.isPlayable` and `OfflineQueueNavigation` treat both tiers alike. `PlaybackCachePipeline.isCachedStream` recognises download-tier URLs, so `isCurrentTrackCached`, standby retention and offline handoff work unchanged. `cachedPlayableTrackIDs`, Search's offline matching and the "Cached on this device" row badges count both tiers.
- **Inventory separation**: `MusicAppModel.temporaryCachedSongs` excludes downloads. Cached Songs is reached through Settings > Library & iCloud > Storage, not a Library management row. Downloads lists permanent files and Storage reports each tier separately. Player captions prefer Downloaded over Cached on This Device. Protected old encodings remain accounted for until their readers retire.
- **Downloads never count** against `AudioCacheLimit`, are never eviction victims, and `clearUnused`/`removeAll`/`removeSong`/`updatePolicy` never touch them. Usage reports them separately (`downloadedBytes`, `downloadedSongCount`). A downloaded song survives every one of those with zero cache-tier variants left for it.
- **Provider IDs**: `AudioCache.isValidTrackID` accepts `<source>:<id>` per `MusicSource` (`saavn:`, `gaana:`) with the YouTube alphabet after the prefix; bare IDs keep the 11-character rule in `isProviderTrackID`. File names replace the colon with `~` (`saavn~abc123.m4a`); `logicalTrackID(for:)` maps back.
- **Export Audio** requires a complete local copy. The model resolves artwork, then holds a scoped cache reader through export. Output is verified tagged AAC-LC M4A, with timeline/marker-aware decoding and specific failure reasons. A known cover URL that cannot be loaded fails visibly; absent cover metadata can remain absent. Native cover readback supplies `artworkJPEG` and the share preview. Immutable Sendable item-source callbacks support UIKit background requests, and the result lease protects the file. [AUDIO_EXPORT.md](AUDIO_EXPORT.md) owns bounds and remaining user-asset/destination checks.
- **Playback source** is each encoding's optional `playbackSource`, independent of the saved catalog ID. Sidecars and the URL-free background queue preserve it through relaunch, publication, promotion and demotion. Unknown old values stay unknown; signed URLs never supply provenance. Complete files carry no extractor-generation confirmation evidence. Live-radio stations cannot enter downloads or export.
- **All / Super Liked / Liked / Not Liked** filters use current favorite and tier membership. Not Liked means absent from Liked Songs, not a recommendation dislike; Super Liked is the super-liked subset of Liked. Heart toggles update membership without deleting files. Play/Shuffle follows the filtered playable list; the summary still counts all downloads and queued rows stay visible. Empty Not Liked says **All Downloads Are Liked**; empty Super Liked says **No Super Liked Downloads**. The chips share `LibraryFilterChips` with Liked Songs: `ChipFlowLayout` wraps chips that do not fit one line onto further rows (accessibility sizes stack one per row) and the capsule fill follows the selection in 180 ms, none under Reduce Motion. R17 UI-02 passed phone heart-toggle/filter checks in light and dark appearance; R18 UI-02 covers export/extractor workflows.

## Storage layout

```
Library/Caches/Audio/                          purgeable tier (unchanged)
  <key>.m4a | <key>.wav                        complete media
  <key>.json                                   sidecar (no "downloaded" field)
  <key>.opus-<UUID>.m4a + .json                prepared Opus variants
  <key>-<UUID>.part                            in-flight transfer
Library/Application Support/GanaBajana/
  Downloads/                                   permanent tier, isExcludedFromBackup = true
    <key>.m4a | <key>.wav                      same names as the cache tier
    <key>.json                                 same sidecar shape plus "downloaded": true
    <key>.opus-<UUID>.m4a + .json              promoted Opus variants
  downloads-queue.json                         v2 URL-free operations; reads legacy v1 IDs
  DownloadStaging/                             token-named deliveries/receipts, excluded from backup
tmp/Export/<UUID>/<artist> - <title>.m4a       verified AAC; retained results protected from pruning
```

`<key>` is the recording ID with `:` replaced by `~`. A tier move writes the target sidecar, renames the media, then removes the source sidecar, so a crash leaves at most one verifiable pair plus a stray sidecar that `verifiedEntry` ignores. The download tier holds one file per song: promotion moves the best playable variant and removes the others; a better encoding prepared later takes the file's place through the same rename. The cache tier's two-variant Opus rotation never counts or removes download-tier variants, and a downloaded song's newly prepared variant bypasses that rotation because it leaves the cache tier at publication. Pending removals live in memory only; a relaunch relies on the inventory-load dedupe instead.

## APIs

- `AudioCache`: `init(directory:downloadsDirectory:...)`, `downloadsDirectory`, `promoteToDownloads(_:) -> DownloadTierChange` (`moved(bytes)` carries the kept file's bytes, `alreadyThere(bytes)`, `notFound` when no playable variant exists), `demoteToCache(_:) -> DownloadTierChange`, `deleteDownload(_:) -> DownloadDeletion` (`deleted(bytes)`, `demotedInUse(bytes)`, `notFound`), `isDownloaded(_:)` (disk answer, also refreshes the index), `nonisolated isDownloaded(trackID:)` (index answer: no disk read or actor hop, false before the first inventory read or tier move), `hasCompleteCopy(of:allowOpus:)`, `transferProgress(for:)`, static `maximumLoadDedupes`, `storageKey(for:)`, `trackID(forStorageKey:)`, `isDownloadedMediaURL(_:)`, `installed`/`install()`. `CachedAudio.isDownloaded`, `CachedSong.isDownloaded`, `Usage.downloadedBytes`/`downloadedSongCount`, `Sidecar.downloaded`. Maintenance (`clearUnused`, `updatePolicy`, `removeSong`) rejects tier moves with `ManagementError.clearing` while it runs and retries pending removals first. Every pre-WP19 signature is unchanged; the WP19 additions are additive.
- `AudioDownloader.receive(..., progress:)` reports `(written, expected)` per 256 KiB chunk; `AudioCache` exposes it as a fraction.
- `ConnectivityMonitor`: `isExpensive` (observable), `isExpensivePath` (thread-safe), `onExpensiveChange`, `setExpensive(_:)`; `init(initialStatus:isExpensive:monitorsSystem:)`.
- `DownloadManager` (actor, `Sources/Downloads/`): `init(store: any DownloadTierStore, transfer:, connectivity: any DownloadConnectivity, queueFile:, configuration:)`, `enqueue(_:) -> Int`, `cancel(_:)`, `cancelAll()`, `retry(_:)`, `clearFailed()`, `setAllowCellular(_:)`, `connectivityChanged()`, `restore(resolvingTracks:)`, `removeDownload(_:)`, `deleteDownload(_:)`, `localCopy(for:)`, `setObservers(onChange:onTierChange:)`. `Configuration` holds concurrency (2), attempts (3), backoff, poll interval and `allowOpus`.
- `DownloadCenter` (`@MainActor @Observable`): `items`, `pendingItems`, `failedItems`, `recentlyDownloadedIDs`, `isAvailable`, `state(for:)`, `isQueued(_:)`, `collectionState(for:downloadedIDs:)`, `download(_:)`, `cancel(_:)`, `cancelAll()`, `retry(_:)`, `removeDownload(_:)`, `deleteDownload(_:)`, `localCopy(for:)`, `restoreQueue(resolvingTracks:)`, `inventoryRefreshed(downloadedIDs:)`. `.unavailable` is used when the player has no local audio store.
- `MusicAppModel` exposes download state, inventory, collection/liked actions and `exportAudio(for:)`. Production builds `DownloadManager.background` from `AudioCache.installed` and the composite resolver's `backgroundDownloadPlan(for:)`. `restoreDownloadQueue()` is shared by initialization, recovery and the app delegate. Preference changes flow through `updatePreferences`; lifecycle calls `downloads.setForeground`.
- `AudioExporter` (actor, `Sources/Export/`): `export(track:source:artwork:) -> AudioExport` includes `transcoded` and `hasArtwork`; success is tagged AAC. Whole-operation budget is 120 seconds with draining cancellation, at most two operations. [AUDIO_EXPORT.md](AUDIO_EXPORT.md) owns the complete API/error and test tables.
- Fixture (DEBUG only): `DebugCachedAudioFixture.makeDownloadCenter(directory:connectivity:)`; the fixture resolver's `download(_:)` publishes the local fixture AAC for an uncached seeded song before promoting, so UI tests download without any network request. `--cache-fixture-downloaded` (with `--cache-fixture`) seeds Tum Hi Ho as a downloaded AAC plus an unprepared Opus variant in the cache tier, the legacy shape; the fixture's own verification snapshot asserts the load-time dedupe left one variant and no cache file (skipped when `--cache-fixture-in-use` may have pinned the song first). `tools/audit-release.py` rejects the `--cache-fixture` prefix, `DebugCachedAudioFixture` and, since WP19, `--recap-history-fixture`.

## Not verified

- A real prepared Opus variant replacing a downloaded AAC on a device; the replacement path runs with the stubbed preparation only. The pending-removal timing under a live AVPlayer (a stale original deleted after playback moves on) is covered by pin and unpin in unit tests, not by a playback run.
- Actual OS suspension/termination, locked-device transfer and UIKit background wake. The background session is integrated; fixture/core tests do not prove OS execution.
- Physical-device backup exclusion and iCloud behaviour; `isExcludedFromBackup` is asserted on the simulator file system only.
- Real device Opus-to-AAC export and recipient-app playback. Native local fixture conversions passed in the coordinator's targeted runs; no original-Opus export fallback remains.
- R17 has targeted phone/SE/iPad light/dark Not Liked Downloads coverage in [VERIFICATION.md](VERIFICATION.md). That does not establish the full Downloads/collection-capsule Dynamic Type matrix; R18 small-phone/iPad checks remain pending.
