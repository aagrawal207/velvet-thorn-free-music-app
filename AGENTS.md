# Breezy

Native iPhone and iPad app (Mac through Designed for iPad on Apple silicon; Mac Catalyst is unavailable because FFmpegBridge ships iOS slices only) using Swift 6, SwiftUI, AVPlayer, and iOS 18+, with a watchOS 11+ companion and native CarPlay audio integration. Selected App Store name: `Breezy - Stream Music & Chill`; Home Screen name: `Breezy`; App Store Connect app `6815025307`. Keep `GanaBajana` as the project/module/folder, `com.agraabhi.ganabajana` as the bundle ID, and the existing library path and product IDs. Branding must preserve installed data.

## Code and persistence contracts

- `project.yml` is the XcodeGen source of truth. Build outputs belong in `artifacts/`. The coordinator owns regeneration and builds during coordinated work.
- Normal `GanaBajana` and `GanaBajanaWatch` schemes use Debug/Release without the managed CarPlay entitlement. Only `GanaBajanaCarPlay` uses Debug-CarPlay/Release-CarPlay and `Signing/CarPlay.entitlements`. Apple approval/profile coverage is required for that scheme. Never add this entitlement to the Watch target or default configurations. Both Release variants exclude `TipJar.storekit`.
- Reuse shared models and provider protocols in `Sources/Core/`. [ARCHITECTURE.md](docs/ARCHITECTURE.md) records the concrete APIs; do not introduce parallel track, playlist, artist-credit, or lyrics models.
- `MusicAppModel` coordinates views, `PlayerController` owns playback, and `LibraryStore` owns saved state. Mutable UI services are main-actor isolated; network providers are actors.
- Watch and CarPlay use one `CompanionPlaybackController` installed in `CompanionRuntime` during app initialization. Reuse the existing player/model actions and preserve their callbacks. Foundation-only transport projections live in `Sources/Core/Companion`; the watch target has no catalog, account, or streaming dependency.
- `BreezyWidgets` shares only a bounded derived snapshot through `group.com.agraabhi.ganabajana`. Keep the library in its installed location, publish after durability, and keep account/audio/provider code out of the extension. `docs/WIDGETS.md` owns projection bounds, privacy, refresh, routes and coverage. The phone's standard/CarPlay entitlements include the App Group; the extension requests only that group, and the Watch requests none.
- Preference changes go through `MusicAppModel.updatePreferences(_:)` so persistence failures and dependent playback/DNS/cache settings stay consistent.
- Library writes are versioned and atomic. Preserve corrupt, unsupported, future-version, or externally changed stores and surface the error. Fixtures use isolated storage and remain excluded from Release.
- Library format v3 reads v1/v2, and journal/replica v2 reads v1 without restamping existing edits. Migration becomes durable on a real write. Shared edits and the sync journal commit atomically even with sync off. `ICloudLibrarySync` merges per-installation replicas; preserve deletion markers, independent preference/playlist fields, typed-search floors and history/search reset generations. Playback, credentials, pending alerts, tips and cached media stay device-local. [ICLOUD_SYNC.md](docs/ICLOUD_SYNC.md) owns these contracts.
- Normal phone builds use `Signing/iCloud.entitlements`; CarPlay configurations include iCloud plus their managed entitlement. The Watch requests neither. Start native sync only for real app launches, never fixture/unit hosts. Apply durable remote changes through `onCloudSyncApplied` without replaying local edits or replacing playback/navigation.
- `recordListening` and `onListeningProgress` return a durable Bool acknowledgement. Keep rejected deltas in the bounded session buffer and pause before dropping them. Clear/history-disable boundaries retire pending time; `reloadSavedLibrary()` validates disk state, reconciles preferences, and preserves newer playback intent.
- A failed-startup empty placeholder must not overwrite a repaired saved queue through lifecycle or restore callbacks. Restore recovered startup state paused only while that placeholder remains untouched.
- Persist recording IDs and metadata, never signed media URLs. Playback generations reject stale extraction, seek, transition, and radio callbacks. Restored playback stays paused; listening time excludes pauses and seek jumps.
- `PlaybackSnapshot.originalQueueIndices` is a validated optional occurrence-to-original-position permutation, preserving identical duplicates after relaunch/unshuffle. Mapping-only edits persist locally. Passive legacy restore/checkpoints retain the absent field until order or selected occurrence changes; never rewrite a repaired startup snapshot just to add metadata.
- `shuffleStyle` and `discoveryFamiliarity` are independent scalar preferences with Random/Balanced missing-field defaults. Sparse v3/v2 journals need no new revisions or format bump. Present invalid values fail closed. The post-durability `onCloudSyncApplied(previousPreferences, recommendationsChanged)` callback applies services while avoiding Home invalidation for shuffle-only or clock-only merges; combined content/history changes still refresh it.
- Recently opened Search results hold at most 20 explicit `SearchSelection` destinations, deduplicated by kind and case-sensitive provider ID. Submission/debounce, generic playback and Back do not record selections. Collection payloads omit embedded tracks. Clear removes both typed recents and retained legacy queries; asynchronous artist resolution must respect the search-reset revision. Home layout and recording-language corrections persist in the library.
- `TipJarService` accepts only its five consumable product IDs. Verify and durably record a transaction before finishing it; preserve deduplication and refund records. Tips grant no entitlement, features, or music. Purchase labels use StoreKit's `Product.displayPrice`.

## Provider and data contracts

- All playback is audio-only. Prefer album-audio recordings and song charts. The current extraction/caching integration is unofficial; successful playback is not distribution permission.
- `YouTubeDataAPI` supplies exact-recording audio language and lookup-only missing duration. Prefer `snippet.defaultAudioLanguage`, never `defaultLanguage`, site locale or country. Cached/explicit language metadata skips recognition; missing/failed metadata keeps the bounded fallback. `docs/YOUTUBE_DATA_API.md` owns limits, metrics and tests. Keep the restricted client key in the ignored local plist, out of logs, source control and companion bundles; release input manifests include only its hash.
- `ListeningLanguageProfile` learns from qualified plays in the last 30 days. Five recording languages and Unclassified use existing evidence; More/Automatic/Less nudges change weights, never statistics or playback eligibility. `MusicLanguage` remains the legacy Hindi/English editorial/chart type; saved language choices provide cold-start weights only. Provider region, artist nationality and station tags do not prove a recording's language. [LISTENING_DISCOVERY.md](docs/LISTENING_DISCOVERY.md) owns weighting and checks.
- `Track.credits` is the artist source of truth; `artists`/`artistID` are derived. Parse linked artist runs, album `straplineTextOne`, and feature clauses. `MusicAppModel.openArtist(_:)` resolves title-only credits by name.
- “This is [artist]” sorts available provider-labelled song plays, unknowns last. Never substitute upload views or weekly/monthly counts, sum versions, or invent a missing total. A validated audio counterpart may retain a count through a single explicit track-credits link with matching title and artist. `PlayerController.currentPlayCount` owns the player's displayed total; `resolvedViewCount` is upload-level diagnostics only. Keep `ArtistPage.monthlyAudience` with its provider value, unit, and raw wording; never turn listeners into monthly plays. The spotlight service always runs its bounded two-page songs search.
- `ArtistSpotlight.displaySongs` selects one display representative for matching releases, retaining meaningful qualifiers, complete performer identity and group-wide duration/language compatibility. Missing durations or ambiguous matches stay separate. A saved correction keeps its recording ID; the selected release retains its own count, explicit flag, artwork and duration. Keep bounded raw candidates across updates. `ArtistSpotlightLoader.listedTracks` and `featuredTracks` share group provenance so an album promotion cannot repeat a listed song under Featuring. `mergedTracks`/`sorted` remain exact-ID operations. [PROVIDERS.md](docs/PROVIDERS.md#radio-and-language-evidence) owns matching and ranking details.
- Recording-language evidence may come from metadata, matched lyrics, or MusicBrainz work metadata. Recognition keeps original text in 40-word cores at a 20-word stride. Only an ambiguous core that passes its own lexical/script checks and has no confident foreign code gets one context retry, capped at 80 words. Preserve the independent foreign-segment veto and sparse-line anchor/confidence requirements; song/artist priors and artist country are never proof. Uncertain or conflicting results stay in All/Unclassified; a persisted correction takes priority. [SONG_LANGUAGES.md](docs/SONG_LANGUAGES.md) owns the thresholds and measured scope.
- `ArtistSpotlightMusicBrainz` requires a real HTTPS `MusicBrainzContactURL`; `project.yml` supplies the published Support Gist anchor recorded in `docs/app-store/PUBLIC_PAGES.md`. Fetch an exact linked work ID only when a compatible recording/work relation lacks embedded language values. Keep the shared one-request-per-second limiter, bounded cache, and lookup/source deadlines in [PROVIDERS.md](docs/PROVIDERS.md#radio-and-language-evidence).
- LRCLIB is the primary lyrics source; `CompositeLyricsProvider` can use recording-linked YouTube Music plain lyrics as fallback. Preserve LyricFind/Musixmatch credits when supplied through YouTube Music. Never invent timestamps or contact those publishers as if a direct integration existed.
- Album descriptions come from the selected album header's attributed Wikipedia prose, with title/type/artist or composer identity checked against that same header. Retain the supplied article and license version; omit missing or conflicting evidence. Reads are bounded, cancellable and nonblocking. [ALBUM_DESCRIPTIONS.md](docs/ALBUM_DESCRIPTIONS.md) owns the source and matching contract.
- Provider weekly charts retain reporting dates, region, and original ranks. Personal recap uses local rolling 7/30/365-day history; never synthesize global monthly/yearly charts.
- Personal mix ranking runs on device. Dislikes are excluded from generated mixes and autoplay; explicit user selections remain playable. Mixes are stable within their period key.
- Discovery balance affects Home shelves and future mixes through `DiscoveryFamiliarity.familiar/balanced/newMusic`. All Daily Mix modes classify heard/unheard songs consistently, using `TasteProfile.heardTrackIDs`; available pools and artist caps bound the target. Weekly keeps unheard recordings and changes known-artist ranking. Capture the preference in Home cache/task identity and pre/post-await mix fences. [LISTENING_DISCOVERY.md](docs/LISTENING_DISCOVERY.md) owns numeric weights, metrics and coverage.
- Fewer repeats uses positive seven-day qualified-listening weights when a new shuffle starts. Read saved history on demand; history off or unavailable storage supplies no evidence. List Shuffle samples the first song and remainder together; explicit selection stays pinned. Preserve every occurrence, original order, manual edits and Repeat one. Changing the preference does not rerank active playback.
- Ordinary autoplay uses `catalog.radio(seed:)` without a Home language filter and at most three provider calls per exhaustion event (`AutoplayContinuation`): ending song, one borrowed queue song and one transient fresh retry. A provider cooldown ends the event. Queue end permits one forced event before pausing with a retry. Automatic Home mixes also use unrestricted radio with on-device soft language ranking; legacy targeted catalog APIs do not filter that path. Known-offline continuation makes no provider request.
- Experience radio has 34 stations under Search > Radio. Automatic startup captures the listening profile and allocates existing cue/style budgets across its languages. Dominant-language mismatches must not let unrelated fixed cues define the station. Active sessions freeze their weights until a privacy reset, without interrupting playback. Era, wording and cue tags do not certify queued languages.
- Bounded startup radio retries, manual continuation, and Autoplay's forced retries use `radio(seed:forceRefresh:)`. Fresh requests bypass stale cached radio responses, not provider cooldowns; keep the documented budgets (style queries 3, playlists 2, date-lookup artists 2, radio requests 10).
- Apply body-size limits while receiving, including missing/chunked lengths, and cancel only the affected request. Artwork coalescing tracks each waiter and cancels/drains the transfer after the last waiter leaves. Provider response/deadline limits belong in `docs/PROVIDERS.md`.
- Release alerts use durable pending IDs. Recheck eligibility after asynchronous identifier lookup and initiate submission in the same main-actor turn. Retire pending alerts on disable/unfollow, and acknowledge platform acceptance without duplicate submission.
- `AudioCacheLimit` owns five byte/song limits. Cache inventory groups immutable encodings, lists only complete compatible copies as playable, and preserves actual bytes. Per-song removal uses the existing maintenance barrier and reports in-use retention. Eviction balances recent and repeat listening; protected readers survive and speculative admission cannot displace higher-scored songs. Complete audio has no TTL but remains purgeable. [LISTENING_DISCOVERY.md](docs/LISTENING_DISCOVERY.md) owns the score; do not promise permanent downloads or lossless audio.
- Reuse `SourceAudioQuality` in `ProviderProtocols.swift`. Rank eligible AAC/Opus by valid average bitrate, then advertised bitrate when needed; prefer AAC on ties. Keep AAC fallback and the iOS 26.5+ gate for native Opus. More displays source metadata, not measured output fidelity or a guaranteed Premium tier.
- Opus WebM must be fully downloaded, packet-copied locally into MP4 through FFmpegBridge, and validated by native PCM output before publication. FFmpeg supplies no network, encoder, or decoder. Playback remains AVPlayer-owned; operation budgets and APIs are in `docs/ARCHITECTURE.md`.
- Cache encodings are immutable variants of one logical song. Preserve in-use originals, publish prepared variants only after validation, and let later plays reuse the best compatible copy. Usage includes all committed encodings and active preparation bytes; the song limit counts logical IDs. Failed/cancelled preparation must not publish a variant.
- Optional YouTube cookies are stored separately in the device-only, after-first-unlock Keychain and added only to TVHTML5 player requests. Catalog transport stays account-cookie-free. Avoid claims that provider requests are unidentifiable or that backups never leave the device.
- Persist sign-out intent before Keychain deletion. A successfully saved credential-free marker blocks session restoration after a failed deletion; failed intent persistence must remain a visible retry-before-closing error.
- Remote extraction stays opt-in. [PROVIDERS.md](docs/PROVIDERS.md) owns payloads and retention; keep it and [PRIVACY.md](PRIVACY.md) aligned with network behavior.
- YouTubeKit is vendored under `Vendor/YouTubeKit`; keep its patch minimal and preserve the MIT license verbatim. Provider credits do not grant rights to music, lyrics, or cover art.
- `Vendor/FFmpegBridge` owns the LGPL wrapper, pinned source, recipe, and provenance. Preserve its bundled notices and original corresponding-source materials. The separate public `Breezy-FFmpegBridge` repository/release supplies the library source and rebuild instructions; recipient application replacement/relinking remains unverified. `docs/FFMPEG_DISTRIBUTION.md` owns the publication mapping and remaining requirement.
- FFmpeg patch policy checks every required patch forward or reverse and rejects conflicts, including source overrides. Verification checks current recipe/patch hashes. The public archive omits only non-build Xcode per-user metadata and retains all build inputs byte-for-byte; preserve the original binary/provenance instead of rewriting it to match the publication repack.
