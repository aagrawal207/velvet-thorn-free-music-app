# Breezy

**Breezy - Stream Music & Chill** is a native iPhone and iPad music app for iOS 18+, built with Swift 6, SwiftUI, and AVPlayer. It also runs on Apple silicon Macs as an iPad app (Designed for iPad). It has audio-only playback, personal mixes, radio, and recording-matched lyrics. A native watchOS 11+ companion and CarPlay audio interface control the same player from the paired iPhone. Native Liquid Glass is used on iOS 26+ with older-system fallbacks.

**App Review submission is on hold for content rights.** The current implementation uses unofficial YouTube extraction and complete-song caching. The owner has confirmed that authorization from YouTube and the rights holders has not been obtained. A licensed provider/content approach must be selected before submission. See [release status](docs/app-store/RELEASE_STATUS.md) and [provider limitations](docs/PROVIDERS.md#distribution-and-content-rights).

## Current features

- **Recording metadata before classification.** The official YouTube Data API supplies audio-language tags when available; explicit tags and cached results avoid lyrics recognition. Missing metadata keeps the existing bounded fallback. Missing duration can be supplied to lyrics/MusicBrainz lookup copies without changing the saved track or current playback. [YouTube metadata](docs/YOUTUBE_DATA_API.md) records scope, configuration and measured coverage.
- **Home Screen widgets.** Recently played, Liked songs and Mix come in small, medium and large sizes. Choose Daily Mix or Discover Weekly when editing a Mix widget. Taps open saved music through Breezy's existing player, including compatible cached audio offline. Widgets use a bounded local metadata/artwork copy; history off hides recent songs. [Widget contracts](docs/WIDGETS.md) cover refresh, privacy, routes and tests.
- **Home that you arrange.** Recently played comes first by default. **Settings > Discovery > Customize Home** saves section order and visibility. Daily Mix, Discover Weekly, followed-artist releases, and dated weekly chart picks appear when data is available. Compact artwork corners and mix titles below the art keep the layout simple.
- **Search and recently opened music.** Blank Search starts with liked/cached songs, live playlist shortcuts and a separate Radio page. Up to 20 explicitly opened songs, artists, albums, playlists or mixes are saved as typed destinations; submitting query text does not add history. Filters appear once a request starts for the current query. Reselecting Search returns from native destinations, keeps the warmed results/query, and focuses with one scroll, respecting Reduce Motion.
- **Search inside your library.** Liked songs and playlists filter local titles, credited artists and album names case/diacritic-insensitively. Play and Shuffle capture the matching songs; filtered removal uses recording identity, and reordering resumes after leaving search. Find music returns to the Search root.
- **Listening languages.** Recap and Settings show counted plays from the last 30 days across five recording languages, including Unclassified in the totals. Optional **More**, **Automatic** and **Less** guide discovery without changing statistics or excluding unknown-language music. Active-app checks can fetch recording metadata and matched lyrics after listening; history off pauses new learning. [Listening-led discovery](docs/LISTENING_DISCOVERY.md) owns the evidence, bounds and test mapping.
- **Thirty-four mood and genre radios.** **Search > Radio** groups stations as Moods and Genres, from Melancholy and Workout to Qawwali, Lo-fi, and Golden oldies. Languages follow the listening profile; no language selection is required. Choose an era preference and zero to four optional artist hints. Station cues, style searches, provider playlists and related-song radio build the queue within shared budgets. Preferences guide discovery rather than certify every track; unavailable results have an error and retry path.
- **Artist pages with sources.** “This is [artist]” opens on popular songs sorted by provider play count, with unknown counts last. **Languages** opens optional filters and correction controls; it becomes **Browse by language** once at least two recording languages are identified. Background results and corrections keep the chosen filter, including an empty one. Uncertain songs remain in All/Unclassified, and artist nationality is never language proof. Monthly audience figures retain the provider's metric and wording. Artist pages add **Featuring [artist]** for songs where the artist is a featured or secondary credit, found through search and sorted by the same counts. A song released as an album track and again as a single or reissue appears once, preferring the album release; live, remix, acoustic and labelled language versions stay separate.
- **A one-handed player.** Full-screen Now Playing keeps previous, play, and next fixed. Its bottom row has native AirPlay, Lyrics, a combined Album and artists chooser, and Queue, with matching compact icons; shuffle and repeat live at the top of Queue. Returning from the background shows the screen you left; the player opens from the mini-player. The mini-player shows progress as a subtle left-to-right fill across its full capsule background. Its 64-point minimum height grows with Dynamic Type, and reserved space covers pushed pages as well as tab roots. Volume uses system controls.
- **Listening controls.** Crossfade defaults to 0 seconds and Automix defaults off, grouped together in Settings. Existing saved choices are preserved. Gapless playback, Autoplay, volume normalization and a sleep timer remain available. Multi-artist choices open immediately; optional artist pictures load afterward without delaying selection. Autoplay filters disliked songs and duplicate song versions. When a song's radio runs dry it borrows another queue song's radio and retries once; if nothing is found, the Queue sheet says why and offers **Try more songs**.
- **Save the remaining queue.** **Queue > Save remaining songs** captures the current and upcoming visible order when the naming sheet opens. Recording IDs are deduplicated only in the saved playlist. One atomic save preserves queue occurrences, playback position, shuffle and repeat; a failed save keeps the draft for retry.
- **Listening preferences.** Icon-labeled Settings offers **Shuffle order > Fewer repeats**, favoring less-recently played songs in the next shuffle, and **Discovery balance > More familiar / Balanced / More new** for new Home recommendations and future mixes. Saved current-period mixes and current playback keep their selection. Both preferences persist and sync independently; history off makes shuffle random without erasing the saved choice. [Listening policies](docs/LISTENING_DISCOVERY.md) records the bounds.
- **Cached and offline listening.** **Cached songs**, available from Search and Storage, shows local availability and per-song removal across cached versions. Known-offline Search uses saved metadata; Home keeps library/cache routes available. Playback uses complete compatible local copies and can skip missing queue entries in order. Reconnection does not start paused playback. Cached audio remains purgeable.
- **Source audio details.** More shows available encoding metadata and offers **Reload best available audio** when not known offline. More and Queue show compact current/next cache captions. On iOS 26.5+, eligible Opus audio is prepared locally for native playback, with AAC fallback. A successfully prepared higher-bitrate cache variant can be reused on later plays while existing in-use files remain protected.
- **Lyrics when available.** LRCLIB is primary; a recording-linked YouTube Music lookup supplies plain-text fallback. Timed lyrics require matched source timestamps. Source credits include LyricFind or Musixmatch when YouTube Music supplies that attribution. Timing adjustments sit in one compact row at the bottom of the lyrics sheet.
- **Album descriptions when available.** **About this album** starts at three lines with **Read more** / **Show less**. It uses Wikipedia prose already supplied in the selected YouTube Music album header, retaining the article link and supplied license. Conservative album and artist/composer checks omit uncertain matches. There is no automatic Wikipedia fetch or added account requirement.
- **Artwork-led collection pages.** Album covers grow to 360 points; circular artist pictures use 90% of that responsive size. Album, mix and playlist rows show known song lengths, with count and complete running time at the bottom. Album and artist pages share the player's artwork-blended backdrop, which tints the whole page with the cover's own colours like the lock screen while keeping text readable.
- **iCloud sync.** Sync defaults on when this device has no saved sync setting, while a saved Off choice stays off. **Settings > Library & iCloud > iCloud sync** shows a green enabled icon, activity status and manual retry. Likes, playlists, follows, history, typed Search selections, preferences and saved metadata merge through your iCloud Drive. Language nudges merge independently per language. Current playback, sign-in, tip records, derived classification caches and media stay on each device. [Sync contracts](docs/ICLOUD_SYNC.md) describe schema migration, reset generations and recovery.
- **Provider song totals.** Available catalog play counts stay attached to the selected recording, including validated album-audio counterparts. Upload views and weekly charts have different scopes and are not displayed as song totals. Unknown counts stay hidden; rounded and saved metadata remain snapshots. [Count semantics](docs/PROVIDERS.md#song-play-counts) records the sources and limits.
- **A saved library and personal recap.** Likes, playlists, follows, queue position, and history persist locally. Failed listening saves remain buffered during the session, with a protective pause at capacity. **Reload saved library** validates recovered disk state while keeping current playback. Recap uses rolling week/month/year windows; pending local release alerts survive relaunch and can retry.
- **Apple Watch controls.** The native watchOS 11+ companion offers Now Playing controls, favorites, recently played, playlists, and queue browsing. Primary transport controls sit above progress. Selecting a song plays it on the paired iPhone. The iPhone owns playback and its audio route; the Watch has no standalone audio playback. Cached or disconnected state is labeled **Last seen on iPhone** with playback actions disabled.
- **Native CarPlay audio.** Favorites, Recently played, Playlists, Queue, and the system Now Playing screen share the iPhone player and library. The custom CarPlay app requires the opt-in `GanaBajanaCarPlay` scheme, Apple capability approval for the App ID, and a matching provisioning profile. Approval and signing remain unverified.
- **Appearance choices.** Settings offers 7 original icons: **Leafnote** (default), Drift, Moonleaf, Ripple, Tide, and the two rose-pen variants **Thorn** and **Sonnet**, whose pens point toward the lower-left through the rose. A device that had a retired icon selected shows Leafnote and is reset to the primary icon once. The App icon row is hidden on a Mac running the iPad app, where alternate icons are unsupported. Seven accent palettes and dark, light, or system appearance remain available. Leafnote is the icon name, not an app rename. Settings groups Playback, Library & iCloud, Appearance, Discovery, Account & connection, and About Breezy with consistent spacing and compact 44-point rows. Native-switch visuals in Settings and Home customization are 20% smaller while retaining full-row taps and native switch accessibility semantics; language nudges use menus.
- **iPhone, iPad, and Mac layout.** Content columns widen to 1000 points in regular width, Home carousels bleed to the window edges, and the mini-player and banners cap at 640 points centered. Hardware keyboards do not hide the mini-player. iPad supports all four orientations and multitasking; multiple iPad windows share one navigation state.
- **Storage controls and optional tips.** Settings shows actual cache and library usage and lets the listener clear unused audio/artwork. Search offers individual removal and Clear all for Recently opened. Five one-time consumable tips unlock no features or music.

The audio cache defaults to **1 GiB or 200 logical songs**, with five size choices. Usage includes every committed encoding and active preparation bytes. Complete audio has no TTL; durable listening recency/frequency guide eviction within the byte/song limits, with in-use files protected. Ordinary playback uses the best compatible cached variant; iOS can purge it, and uncached music needs a connection. There is no managed offline-download library or guaranteed source bitrate. See [cache policy and audio quality](docs/PROVIDERS.md#audio-cache-and-quality).

Language inference keeps original punctuation, contractions, and line breaks in overlapping 40-word windows, with one bounded context retry for an otherwise valid ambiguous core. Foreign-segment vetoes and lexical anchors remain required. The earlier four live language cases passed, including Kanye West's **All Falls Down (feat. Syleena Johnson)**, Radiohead's **No Surprises**, Hindi/transliteration, and the exact MusicBrainz work contract. MusicBrainz can conditionally fetch an exact linked work whose embedded language fields are missing or empty; these results establish neither catalog-wide accuracy nor incremental live recovery from that extra request. [Recording languages](docs/SONG_LANGUAGES.md) records the evidence.

Provider requests go directly from the device; there is no Breezy app backend. The paired Watch receives recording metadata and library rows through WatchConnectivity, without audio, media URLs, account cookies, or artwork assets. Optional YouTube account cookies are held separately in the device Keychain and used only for a specific playback lookup. Remote extraction is off by default. Library data may be included in device backups, and providers receive request data and network addresses. [Privacy](PRIVACY.md) describes those distinctions.

## Development

Developed with **Xcode 27**, **Swift 6**, and **XcodeGen**. From the repository root:

Configure official metadata with `python3 tools/configure-youtube-data-api.py`. The helper stores the app/API-restricted client key in `Resources/YouTubeDataAPI.local.plist`, which is ignored by Git. Regenerate the project after creating the file. Unit and fixture hosts use injected providers; the explicit live API test reads the bundled credential. [Configuration and limits](docs/YOUTUBE_DATA_API.md#local-configuration-and-release) explain the native client and development-only ytmusicapi probe.

```sh
xcodegen generate
open GanaBajana.xcodeproj
```

Select `GanaBajana` and the dedicated **GanaBajana QA iPhone 17 Pro** simulator for phone work, **GanaBajana QA iPhone SE 3** for compact accessibility checks, an iPad simulator or **My Mac (Designed for iPad)** for the regular-width layout, or `GanaBajanaWatch` and the paired **Watch SE 3 (40 mm)** simulator for the companion. `project.yml` configures both apps, the embedded Watch target, and their test targets; the app targets device families 1 and 2 with all four iPad orientations and no `UIRequiresFullScreen`. Mac Catalyst is not an option because FFmpegBridge ships iOS slices only. The coordinator owns project generation and build/test execution. The dedicated **GanaBajana QA iPad Pro 13** simulator ran `GanaBajanaIPadLayoutUITests` for portrait and landscape captures, and the Mac (Designed for iPad) variant built unsigned. [Verification](docs/VERIFICATION.md) records selected phone/iPad workflows and small-phone accessibility checks; a Mac run and physical iPhone, iPad, and Mac acceptance remain pending.

For normal automatic signing, use **`GanaBajana` or `GanaBajanaWatch`**. The phone's Debug/Release builds use `Signing/iCloud.entitlements` for `iCloud.com.agraabhi.ganabajana` and the widget App Group `group.com.agraabhi.ganabajana`, without Apple's managed CarPlay capability. The embedded `BreezyWidgets` target uses `Signing/Widgets.entitlements` for that group only. Choose **`GanaBajanaCarPlay` only after Apple approves the App ID's capability and the provisioning profile includes it**. Its file includes iCloud, the App Group and CarPlay; the Watch requests none of these. See [widget contracts](docs/WIDGETS.md) and [CarPlay signing](docs/CARPLAY.md#audio-entitlement).

| Scheme | Purpose |
| --- | --- |
| `GanaBajana` | Debug development, unit tests, and fixture UI tests; Debug Run uses `Resources/TipJar.storekit` |
| `GanaBajanaWatch` | Embedded native companion, Watch unit/UI targets, and the opt-in paired transport test |
| `GanaBajanaCarPlay` | Opt-in CarPlay signing: Run/Test use `Debug-CarPlay`; Archive uses `Release-CarPlay` |
| `GanaBajanaLive` | Opt-in live provider checks, including experience radio, lyrics fallback, and encrypted DNS/TLS |
| `GanaBajanaLiveUI` | Opt-in live playback UI workflow |

`tools/verify.sh` supports `unit`, `ui`, `watch-unit`, `watch-ui`, `live`, `live-ui`, and `release`, regenerating the project and keeping outputs under `artifacts/`. Live mode includes `AlbumDescriptionLiveTests`. `SKIP_NATIVE_STOREKIT=1` explicitly excludes native StoreKit from phone unit/UI runs; the default is 0. The paired-Watch connectivity test has a separate opt-in and [fixture launch order](docs/WATCH.md#paired-simulator-watchconnectivity). Headless rotation uses the explicit scene-geometry opt-in described in [architecture](docs/ARCHITECTURE.md#verification-ownership).

Release mode creates a local archive, unsigned by default or signed with `RELEASE_SIGNING=automatic`. `python3 tools/audit-release.py <archive> --version 1.0.0 --build 5 --require-youtube-data-api` checks identity, device support, signatures, notices, absent fixtures, widget/App Group and required phone-only API configuration. Both Release configurations exclude `TipJar.storekit`. Current distribution artifacts, input hashes and receipts are under `artifacts/AppStore-1.0.0-5/`; build-3/build-4 artifacts remain frozen. The release input manifest includes the ignored credential file's hash, not its value. [Verification](docs/VERIFICATION.md) records execution details.

The app dynamically links the minimal [FFmpegBridge](Vendor/FFmpegBridge/README.md) XCFramework for local WebM-to-MP4 packet copy, with no re-encoding or network/decoder stack. Homebrew `ffmpeg` only generates fixtures. Framework rebuilding, source repackaging, and package verification are complete; public recipient-source/relink delivery remains unresolved in [FFmpeg distribution](docs/FFMPEG_DISTRIBUTION.md).

If Xcode reports a missing local YouTubeKit package after project regeneration, close and reopen the project to refresh its package graph before investigating package configuration.
